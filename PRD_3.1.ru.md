# PRD Vibix Images 3.1.0

PRD Key: `CG31-PRD-001`

Статус: Draft after consolidated owner feedback
База продукта: готовая исходная версия 3.0.7 (`78f8c63`)
Целевая ветка после freeze 3.0.7: `develop/3.1`
Файл задач: `TASKS_3.1.ru.md`

## Цель

Версия 3.1.0 должна сделать массовую генерацию и обработку понятнее, а локальное
удаление chroma-key фона и ручную коррекцию alpha-маски — заметно качественнее.
Пользователь видит только настройки выбранной операции, провайдера и модели,
получает говорящие имена готовых файлов и может безопасно менять сразу много
промптов.

## Граница версии

- 3.0.7 считается завершённой release-базой и не получает требования ниже.
- 3.1.0 наследует все подтверждённые контракты `PRD_3.0.ru.md`, если этот
  документ явно их не меняет.
- Новые функции реализуются небольшими ветками от `develop/3.1` и
  интегрируются по одной после проверки.
- Сборка, платные запросы и публикация запускаются только отдельной командой
  владельца.

## Принципы

- Сначала пользователь выбирает действие и провайдера, затем видит только
  совместимые модели и параметры.
- Основной интерфейс использует безопасные автоматические значения; технические
  числовые параметры не навязываются без необходимости.
- Исходники никогда не перезаписываются; промежуточные и готовые файлы разделены.
- Одинаковая операция выглядит одинаково в Clipart и Processing.
- В приложение не включаются чужие исходники с несовместимой лицензией.

## Обязательное визуальное согласование

- `CG31-UX-001` — перед кодом любого нового или существенно переделанного
  видимого раздела сначала создаётся визуальный макет в тёмном стиле Vibix.
  Утверждение этого PRD не считается автоматическим утверждением всех экранов.
- `CG31-UX-002` — перед макетом простыми словами фиксируются цель экрана,
  пользовательское действие, границы изменения и элементы, которые должны
  остаться без изменений.
- `CG31-UX-003` — макет показывает экран целиком в контексте wizard, а не только
  отдельный control, если окружающая компоновка влияет на восприятие. Основной
  размер — 1120×780; отдельно проверяется пригодность при минимуме 980×700.
- `CG31-UX-004` — до реализации показываются все существенно разные состояния:
  default/empty, заполненное или включённое, provider/model variants,
  validation/error и правила hidden/disabled. Для переработки существующего
  экрана показываются `Сейчас` и `Предлагается` рядом.
- `CG31-UX-005` — рядом с макетом объясняются действия, переходы и условная
  видимость. UI source нельзя менять до явного ответа владельца
  `Макет утверждён`. Если в коде требуется неутверждённое визуальное изменение,
  работа останавливается и макет согласуется повторно.
- `CG31-UX-006` — после реализации реальные screenshots тех же состояний
  сравниваются с утверждённым макетом. Несовпадение либо исправляется, либо
  отдельно утверждается до закрытия задачи. Для чисто внутренних изменений
  достаточно кратко согласовать ожидаемое поведение без визуального макета.
- `CG31-UX-007` — ранние варианты могут быть схематичными, но финальный макет
  для утверждения должен быть визуально близок к будущему экрану. Approved
  mockup и итоговое сравнение сохраняются с безопасными тестовыми данными в
  `docs/ui/3.1/<task-id>/` и связываются с task/spec, чтобы решение не потерялось
  между сессиями.

## Функциональные требования

### Генерация и промпты

- `CG31-FR-001` — выбор генерации разделён на `Провайдер` → `Модель`. Для
  mixed batch обычная lane и reference lane имеют собственную пару selectors;
  список фильтруется по провайдеру, операции и наличию референсов. Смешанного
  безымянного списка разных провайдеров нет.
- `CG31-FR-002` — только в Clipart под каждым источником промптов
  (конструктор серии, готовый многострочный prompt и CSV) находится одинаковый
  необязательный modifier `Добавить chroma-key фон`.
- `CG31-FR-003` — modifier хранится в metadata каждого `PromptEntry` отдельно
  от пользовательского текста, показывает точный итоговый prompt, выключен по
  умолчанию и при смене цвета обновляет существующий блок без дублирования.
  Series/CSV batch запоминает выбранный цвет в каждой создаваемой строке;
  последующая смена общего control не переписывает уже добавленные entries.
  В Pinterest и Processing prompt modifier отсутствует.
- `CG31-FR-004` — на странице проверки можно применить к выделенным строкам
  (например, 15) или ко всему списку find/replace, insert-after, prepend или
  append. До применения видны область, количество и preview; references и
  порядок не меняются, одна массовая операция отменяется целиком. Редактируется
  только user-authored text; system chroma metadata/rendered block не является
  целью find/replace и не дублируется при prepend/append.

Утверждённый синий шаблон; для red/green меняются только название и HEX:

```text
Isolated on a completely flat, uniform, solid pure blue (#0000FF) digital chroma-key background. The background fills the image edge to edge with no gradient and stays fully bright inside every gap and opening. No reflection, tint, shadow, glow, haze or color spill on the subject. Crisp hard edges, everything in sharp focus, the complete subject centered with at least 10% empty margin, nothing cropped, no text, no watermark, no stray fragments.
```

### Общий редактор обработки

- `CG31-FR-010` — верхний блок `Операции` остаётся компактным. Ниже видны
  только включённые этапы в фактическом порядке: короткий заголовок, controls,
  тонкий разделитель и небольшой интервал. Выключенный этап исчезает полностью;
  тяжёлые вложенные рамки и объясняющие абзацы не используются.
- `CG31-FR-011` — Clipart и Processing используют один
  `ProcessingPipelineEditor`, одну модель recipe и один builder порядка.
- `CG31-FR-012` — первый и второй upscale всегда показывают provider, model и
  допустимый scale. Background removal показывает только параметры выбранного
  endpoint/model: BiRefNet, rembg и Bria controls не смешиваются.
- `CG31-FR-013` — раздел называется `Очистка` и содержит только
  `Удалить служебные данные изображения` и
  `Удалить водяной знак Gemini`, без описательных абзацев и обещаний
  удалить скрытый SynthID.
- `CG31-FR-014` — операция называется `Установить 300 DPI`, остаётся видимой во
  всех применимых маршрутах и изменяет DPI metadata, а не pixel dimensions.
- `CG31-FR-015` — любой chroma-key selector предлагает только pure blue
  `#0000FF`, green `#00FF00` и red `#FF0000`. Custom, HEX input и eyedropper
  отсутствуют; обычные художественные палитры этим не ограничиваются.

### Файлы результата

- `CG31-FR-020` — пользователь выбирает `Рабочую папку`; внутри неё приложение
  создаёт user-visible `rough/` для сохраняемых промежуточных stage outputs и
  `output/` только для готовых `_ready`. Внутренняя transient `.run/` не
  считается `rough`, не показывается как результат и очищается best-effort
  после terminal run. Старый сохранённый путь с basename `output` мигрирует в
  его parent как workspace root с одноразовым уведомлением. Для любого другого
  legacy path до первого 3.1 run требуется одноразовый выбор: подтвердить эту
  папку как workspace root (готовые файлы далее пойдут в её `output/`) или
  выбрать другой root. Без подтверждения фактическая папка результатов не
  меняется, поэтому `output/output` и неожиданный перенос не возникают молча.
- `CG31-FR-021` — промежуточное имя содержит один suffix последнего этапа:
  `_generated`, `_upscaled-before-2x`, `_bg-removed`,
  `_upscaled-after-2x`, `_trimmed` или `_edge-cleaned`.
  Цепочки suffix, timestamps и длинные random IDs не используются.
- `CG31-FR-022` — Processing сохраняет безопасную основу исходного имени;
  Clipart generation использует structured object, а для ready free-form/CSV —
  первые значимые нормализованные слова плюс стабильный row index, с fallback
  `clipart_01`. Pinterest prompt-only использует те же free-form/CSV правила с
  fallback `pinterest_01`. Отдельного поля имени пока нет; collisions получают
  `_2`, `_3` без перезаписи. Corrected PNG сохраняется в `output/` как `_ready`,
  а отдельно сохранённая alpha-mask — в `rough/` как `_alpha-mask`.

### Проверка прозрачности

- `CG31-FR-030` — после результатов открывается отдельная страница
  `Проверка прозрачности`: слева компактный список/миниатюры, справа крупный
  рабочий canvas выбранного файла. Двойной клик по строке выбирает файл и
  переводит фокус в canvas; возврат к Results не теряет несохранённую маску без
  явного подтверждения.
- `CG31-FR-031` — доступны `Вписать`, 25%, 50%, 100%, 200%, ручной процент и
  pan. Курсор показывает реальный outline кисти.
- `CG31-FR-032` — кисть имеет radius и hardness/softness, режимы add/remove и
  рисует непрерывной линией при удержании мыши. Есть undo/redo и reset для
  текущего файла.
- `CG31-FR-033` — preview переключается между шахматным, белым, чёрным и
  яркими проверочными фонами, которые не попадают в PNG. Corrected PNG и alpha
  сохраняются атомарно без повторного платного remover-вызова.

### Независимый Local Chroma Key 2

- `CG31-FR-040` — основной режим работает автоматически и оценивается по
  наблюдаемому результату: сохраняет opaque subject и thin details, создаёт
  естественный partial alpha на краях, очищает внутренние openings и подавляет
  key-color spill без заметного повреждения объекта. Конкретная математическая
  архитектура выбирается только после отдельного исследования первичных
  источников и baseline benchmark.
- `CG31-FR-041` — обязательные `Допуск` и `Мягкость` убираются из основного UI.
  Простые edge profiles допускаются только если benchmark докажет их пользу;
  числовые параметры остаются скрытыми advanced controls.
- `CG31-FR-042` — движок реализуется на уже доступных Pillow/NumPy/OpenCV и
  проверяется собственным golden set. Исходники Clipbrook были изучены как
  research reference, поэтому работа не называется clean-room. Код, структура,
  constants и tests Clipbrook не копируются и не переводятся. Наблюдаемые там
  методы и технические идеи можно использовать как research input: понять их
  назначение, затем самостоятельно реализовать, упростить или улучшить под наши
  изображения. Простая замена названий или чисел в чужом коде самостоятельной
  реализацией не считается.
- `CG31-FR-043` — если ограниченный собственный prototype не проходит
  согласованные сложные cases, принимается stop/continue решение; при stop
  отдельно рассматривается коммерческая лицензия, а не копирование source.
  Отдельный пользовательский или юридический gate в продукт не добавляется;
  действует обычное code review правило не включать чужие файлы и скопированные
  фрагменты. Если позже будет принято решение использовать именно исходный код
  Clipbrook, это потребует отдельного лицензионного решения.

### Параллельность

- Подключение Fal.ai, ключ и показ баланса уже подтверждены в 3.0.7 и не входят
  в повторную реализацию 3.1.
- `CG31-FR-050` — concurrency настраивается отдельно для каждого
  provider/account и делится всеми его операциями. Единого значения вроде `35`
  нет.
- `CG31-FR-051` — KIE, PhotoRoom и Fal.ai имеют отдельный выбор 1/2/3, по
  умолчанию 3 для каждого; все remote requests вместе ограничены
  application-wide cap 6. HTTP 429 вызывает bounded backoff/retry и не теряет
  очередь. Local operations остаются последовательными без доказанной thread
  safety.

## Ограничения и вне scope

- Desktop остаётся Python/PyQt6; новые зависимости не требуются для prototype.
- Custom chroma colors, HEX и eyedropper не входят в 3.1.0.
- Photoshop-подобный редактор слоёв, рисование RGB и AI-перерисовка объекта не
  входят в 3.1.0.
- Методы и идеи, изученные в Clipbrook, можно самостоятельно адаптировать и
  улучшать; его исходные файлы и скопированные фрагменты не включаются в
  закрытое приложение без отдельного лицензионного решения.
- Высокий непроверенный provider concurrency и автоматические paid smoke
  запрещены.

## Приёмка

- [ ] `CG31-AC-001` — provider/model selectors и все processing controls
  показывают только совместимые значения без скрытых defaults.
- [ ] `CG31-AC-002` — Clipart и Processing используют одинаковые динамические
  stage sections; cleanup copy и 300 DPI соответствуют PRD.
- [ ] `CG31-AC-003` — три chroma presets едины для prompt и removal, а modifier
  работает во всех трёх источниках Clipart и нигде больше.
- [ ] `CG31-AC-004` — массовое редактирование меняет только подтверждённый scope
  и сохраняет references/order.
- [ ] `CG31-AC-005` — `rough/` содержит только intermediates, `output/` только
  `_ready`; имена короткие, понятные и collision-safe.
- [ ] `CG31-AC-006` — mask editor поддерживает крупный canvas, zoom presets,
  видимую continuous brush, hardness, add/remove, undo/redo/reset и atomic save.
- [ ] `CG31-AC-007` — собственный chroma prototype проходит числовые и
  визуальные пороги, заранее зафиксированные Task 8 для edges, thin details,
  openings и spill, либо фиксирует честное решение остановить разработку.
- [ ] `CG31-AC-008` — provider concurrency не превышает проверенные limits,
  корректно обрабатывает stop/429 и не смешивает результаты.
- [ ] `CG31-AC-009` — focused tests, full offline suite и ручная Windows
  acceptance проходят до отдельной команды build 3.1.0.
- [ ] `CG31-AC-010` — у каждой реализованной UI-задачи есть утверждённый до кода
  visual artifact и итоговое сравнение с реальным экраном; отсутствующие или
  изменённые без согласования visuals блокируют закрытие задачи.
