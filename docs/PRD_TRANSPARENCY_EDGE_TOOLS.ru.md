## Состав работ (порядок = порядок PR, каждый отдельная ветка `codex/<тип>-<тема>-<дата>` и PR)
1. **Ошибка (docs/ERRORS.md #transparency-lasso-cursor-20261022).** Двойной курсор после «перо → лассо → кисть»;
   Esc закрывает окно вместо снятия выделения лассо. Сброс курсора при смене инструмента; Esc сначала снимает
   выделение, окно закрывает только при пустом выделении. Тест на смену инструмента и Esc.
2. **Курсор кисти на белом фоне.** Контур из двух колец (тёмное и светлое), виден на любом фоне. Размер контура
   соответствует реальному диаметру кисти.
3. **Панель инструментов.** Три кнопки в ряд «Кисть», «Перо», «Лассо» (лассо выносится из блока «Контур» пера).
   Режимы пера (сейчас 2 иконки и 1 широкая) выстроить ровным рядом. Поведение уже существующих режимов не менять.
4. **Кнопки краёв** (общий модуль обработки alpha, без привязки к Qt, чтобы тестировать отдельно):
   - «Края жёстче» / «Края мягче»: меняют только резкость перехода alpha на границе; фиксированный шаг, повторное
     нажатие продолжает. «Жёстче» сужает переходную зону до 2–3 пикселей и не доходит до чистых 0/255 (без «лесенки»);
     «мягче» расширяет зону на такой же шаг. Внутренность и пустой фон не трогаются.
   - «Сузить край» / «Расширить край»: двигают границу на 1 пиксель за нажатие (эрозия/дилатация по alpha),
     убирают светлую кайму. Поля с числом пикселей нет (решение владельца).
   - Область: всё изображение или выделение лассо (если выделение есть, работает по нему, иначе по всему).
   - Каждое нажатие один шаг в истории отмены (Ctrl+Z возвращает ровно один шаг).
5. **Отложено, отдельная большая задача:** свободное лассо в режиме пера выделяет несколько точек контура; выделенные
   точки двигаются вместе и удаляются клавишей Delete. Не входит в пункты 1–4.

## Критерии готовности
- Тесты на каждый пункт (alpha-функции: на синтетических масках с краем 6 px: переход после «жёстче» 2–3 px,
  после «мягче» шире, эрозия/дилатация ровно 1 px, область лассо не затрагивает остальное; Esc и смена инструмента).
- Проверка на белом, тёмном и клетчатом фоне; на реальном клипарте с полупрозрачным краем.
- Скриншоты окна «до/после» для владельца; сборка только по её команде.
- Записать итог в STATE.md, TASKS.md, при ошибках docs/ERRORS.md.
