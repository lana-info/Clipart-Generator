# PRD: модуль Patterns (бесшовные паттерны, `module_id = patterns`) для Vibix Studio

Status: DRAFT v0.3 — 2026-10-21. Не реализовано. v0.1 прошёл ревью архитектуры
2026-10-21 (сверка с кодом: `studio_module_api.py`, `studio_module_runtime.py`,
`studio_modules.py`, `studio_module_delivery.py`, `studio_module_packaging.py`,
`studio_patterns.py`, Prompt Composer, ADR-004, `PRD_VIBIX_STUDIO_3.2_V2.ru.md`
§3, §9–§11). Решения владельца от 2026-10-21 внесены (§9). Нужен UI-approval.

## 1. Цель

Отдельный официальный модуль Studio для создания бесшовных паттернов и наборов
цифровой бумаги (digital paper) для Etsy. Не режим внутри Clipart; Clipart для
работы модуля не обязателен.

Два режима первой версии:

- **A. Из элементов (сцена).** Прозрачные PNG раскладываются на холсте с
  переносом через края (toroidal wrap). Для обычного повтора бесшовность
  гарантирована построением при условии wrap-aware ресемплинга (§4.1). Хранится
  сцена, а не только сведённый PNG. Платных вызовов нет.
- **B. Из готовой плитки.** Пользователь загружает картинку (или получает её из
  AI-генерации, B+) и делает её бесшовной: offset + blend, затем проверка шва.
  Бесшовность не гарантирована — только измерена (Ready / Review / Fail).
  AI-генерация плитки идёт через Core-провайдеров со стоимостью до запуска.

## 2. Исследование (что учтено)

- tiatx.com: страница закрытая (членство); функции прочитать не удалось. Владелец
  решил (2026-10-21) сверку со скриншотами не делать — не блокирует PRD.
- Готовых подходящих решений нет: img2texture (CLI, blend краёв, уменьшает картинку),
  webmemo texture-generator (JS, шум на торе), Tiled Diffusion и circular padding
  (нужна локальная диффузия/GPU, не наши API-провайдеры), SeamlessRepeat (платный
  сервис; ориентир по раскладкам и 300 DPI). Кандидат на будущую стадию B+:
  fal SeedVR2 Seamless (апскейл готовой плитки, не генератор; см. PRD 3.2 v2).
- Вывод: собственный детерминированный движок на numpy/Pillow/OpenCV, расширяющий
  `studio_patterns.py`. Библиотеки уже в `requirements.txt` и поставляются с Core;
  подписанный пакет модуля не может принести свои бинарные зависимости, поэтому
  используемые версии numpy/OpenCV/Pillow фиксируются через `studio_min`.

## 3. Пользователь и сценарии

Продавец цифровых товаров на Etsy.

1. Импортировать свои PNG → задать плотность/размер/раскладку → предпросмотр 3×3 →
   закрепить удачные элементы и пересобрать остальные → набор из N листов
   (разные seed/раскладки) → экспорт.
2. Загрузить плитку → «Сделать бесшовной» → предпросмотр 3×3 со стыком в центре и
   метрика шва → принять или вернуть на доработку → экспорт.
3. (B+) Сгенерировать плитку по промпту (стоимость до запуска, явное
   подтверждение) → сценарий 2.

## 4. Функциональные требования

### 4.1 Движок (чистый Python, без Qt, без сети)

Основа — `studio_patterns.py` (сцена, supertile, wrap-рендер, лимиты). Перед
упаковкой код движка переносится в payload модуля (см. §4.2), Core его не
импортирует.

- `tile_from_motifs` = существующие `PatternScene` + `rebuild_layout` +
  `render_supertile`, доработанные: контроль плотности и минимального зазора
  с измерением на торе (расстояния с учётом переноса), относительная частота
  элементов, закрепление; при невыполнимых настройках — предупреждение и
  ограниченное число попыток, не бесконечный поиск. Мотив трансформируется
  (масштаб/поворот) один раз, затем копии кладутся по решётке с целочисленными
  смещениями периода — копии у противоположных краёв попиксельно идентичны.
  Альфа-композитинг через Pillow `alpha_composite` (корректная straight-alpha
  «over»); premultiplied нужен только при собственном ресемплинге RGBA.
- **Wrap-aware ресемплинг (обязательно).** Любая пространственная фильтрация
  готовой плитки — масштабирование при экспорте 8×8/6×6/custom, подгонка AI-плитки
  к 3600, размытие, суперсэмплинг — выполняется на плитке, дополненной по периоду
  (`np.pad(mode="wrap")` / `cv2.BORDER_WRAP`), с последующей обрезкой. Обычный
  `Image.resize` у краёв клампит пиксели и создаёт шов. Целевой размер при
  масштабировании подбирается так, чтобы период оставался целым числом пикселей.
- `make_seamless` (режим B): сдвиг на половину периода (`np.roll`), затем замена
  креста шва смешиванием с исходником по маске с перьевым краем; без уменьшения
  размера; параметр ширины полосы и силы. Ограничение метода: в полосе
  смешиваются разные участки рисунка — двоение/размытие на сложных рисунках.
  Вариант качества для исследования: шов минимальной ошибки (graph-cut/quilting)
  в полосе вместо линейного blend. «Исправление» не должно сводиться к размытию.
  Метод решает только обычную решётку; для half-drop/brick стыки другие
  (соседняя плитка сдвинута на ½ периода), поэтому в v1 режим B поддерживает
  только straight и mirror, если не реализован lattice-aware вариант.
- `layout`: straight, half-drop (= `half_column`), brick (= `half_row`), mirror
  (4-кратное зеркало базовой ячейки). Для сдвинутых раскладок экспортируется
  прямоугольный полный период (supertile), повторяемый обычной сеткой: при
  квадратном листе 3600×3600 базовая ячейка half-drop = 1800×3600, brick =
  3600×1800, mirror = 1800×1800. Mirror бесшовен построением и для режима B, но
  отражает асимметричные мотивы (текст, направленные объекты) — предупреждать.
- `seam_score`: **не** «различие противоположных краёв» (у хорошего шва крайние
  столбцы и не должны совпадать). Метрика — непрерывность перехода: разность
  соседних пикселей через границу периода (последний столбец → первый, последняя
  строка → первая; для half-drop/brick — с учётом сдвига соседа), нормированная на
  типичную разность соседних пикселей внутри плитки (медиана/перцентиль по
  внутренним столбцам/строкам), отдельно по горизонтальному и вертикальному шву и
  углам; для режима B дополнительно — внутри полосы смешивания (двоение,
  потеря резкости). Статусы Ready / Review / Fail; пороги калибруются на
  размеченном эталонном наборе good/bad до фиксации (T1.4). Технические полосы,
  пустые дорожки и заметный повтор мотива оцениваются отдельно и не делают шов
  «плохим» (PRD 3.2 v2 §10).
- `preview_grid`: 3×3 и 5×5 с ограничением по пикселям (существующий
  `render_preview`, `MAX_PREVIEW_PIXELS`); полный 3×3 от 3600 (10800² RGBA ≈ 470 МБ)
  в память не собирается. Смещение начала так, чтобы стык был в центре.
- `recolor` **вне v1** (решение владельца: функция не нужна сейчас). На будущее:
  только поточечные цветовые операции (сохраняют шов); Style/Palette профили живут
  в слое Clipart и не импортируются (ADR-004); нужен отдельный контракт палитр.
- `export`: 12×12 in @ 300 DPI = 3600×3600 px по умолчанию; также 8×8 (2400),
  6×6 (1800), custom (px или см, `px = round(cm / 2.54 × DPI)`); PNG (sRGB-чанк
  или ICC sRGB, pHYs = 11811 px/m — при чтении это 299.9994 DPI, тест допускает
  округление) и JPG (JFIF 300 DPI, без альфы — прозрачный фон запрещён или
  сводится на выбранный цвет, качество ≥ 90, subsampling 4:4:4); имена файлов и
  порядок листов; отдельное презентационное превью, явно отличное от
  производственной плитки. DPI-метаданные не увеличивают детализацию.
  Лимит Etsy на размер файла не учитывается: файлы выдаются через Google Drive
  (решение владельца). Оценка размера файла до экспорта остаётся как подсказка.

### 4.2 Модуль Studio (сверено с реальным контрактом)

- **Упаковка — по образцу Prompt Composer, а не `studio_official_modules/pinterest`.**
  Pinterest-адаптер использует приватный `_LegacyModuleContext.services`
  (временный путь для старых адаптеров); публичный `ModuleContext` v1 содержит
  только `module_id` и `version`. Новый модуль: каталог payload в корне
  репозитория (`patterns/` или `seamless_pattern/`) с `entry.py`, явная
  инвентаризация файлов (аналог `studio_prompt_composer_package.py`) и ветка в
  `studio_module_packaging.prepare_official_workflow_release`. Внутри пакета —
  только относительные импорты; Core-код импортировать можно только через
  публичные API (`studio_module_api`, `studio_asset_api`).
- `entry.py` экспортирует `register(context)` → `ModuleRegistration` (API v1):
  `PageDeclaration("main", …)`, `CommandDeclaration("kernel", …)` (чистые функции
  движка), `DocumentTypeDeclaration("project",
  "application/vnd.vibix.<module_id>-project+json", 1)`. Имена соответствуют
  `[a-z][a-z0-9_-]{0,63}`. Если понадобятся host-контракты через брокер —
  `capabilities` + `bind(context)`; новые capability (например,
  `studio.patterns-host`) требуют `CapabilityProvider` в Core.
- Команды и фабрики страниц v1 **обязаны завершаться синхронно**
  (`_synchronous_result` отвергает Future/awaitable/генераторы) и выполняются
  под глобальным `_module_execution`-локом. Генерация листа/набора — это
  Core-owned задача (как `ComposerJob`) с `JobLease` от
  `ModuleRuntimeHost.acquire_job_lease`, отменой и прогрессом; модуль не
  запускает неуправляемых потоков. Модули движка импортируются заранее в
  `kernel()`, а не лениво из рабочего потока.
- **Нужен Core-хост модуля** (аналог `studio_prompt_composer_host.py`):
  хранилище проектов и ассетов вне `ModuleStore` (переживает отключение/удаление
  модуля), импорт PNG в content-addressed `AssetStore` с `AssetHandle`
  (sha256), запуск задач с lease, проверка права перед каждым действием и
  перед применением результата, quote → submit для платных запросов.
- Тип документа проекта v1 хранит сцену: версии ассетов (`AssetHandle`), позиции,
  поворот, масштаб, слои, закрепление, seed, параметры, **версию алгоритма**,
  repeat mode, фон, варианты палитры; для режима B — исходник и параметры
  обработки. Исходники не перезаписываются.
- Источник элементов в v1 — импорт своих PNG (в т.ч. папки) через Core-хост.
  Передача из Clipart в v1 **не делается** (решение владельца). На будущее — только
  явное действие со стороны Clipart через версионированный asset-контракт
  (`AssetHandle`); модуль не импортирует слой Clipart (ADR-004; тест
  `test_studio_dependency_architecture`).
- Платная AI-генерация (B+) — только через Core job admission (quote → явное
  подтверждение → submit с повторной проверкой права), ключи провайдеров модуль
  не видит. Скрытых платных вызовов и автоповторов нет.
- Проект и ассеты сохраняются, если модуль отсутствует или отключён.
- Отдельное право (entitlement) по `module_id`; `ModuleAccessPolicy` проверяет его
  на `activate`/`load`/`page:`/`command:`; не входит в `PROCESSING_CONSUMERS`
  (shared `image-processing` модулю не нужен; межпакетные `dependencies` в
  манифесте не поддерживаются).
- Манифест: `module_api: 1`, `studio_min` = первая версия Studio, содержащая
  Core-хост и регистрацию модуля (новый релиз Core после 3.2.16),
  `studio_max_exclusive` (сейчас 3.3.0), `platforms: ["windows-x64"]` до нативной
  приёмки других платформ. Размер пакета ≤ 64 МБ, ≤ 512 файлов.
- **Изменения Core (требуют релиза оболочки):** `DELIVERABLE_IDS` в
  `studio_module_delivery.py`, запись `BUILTIN_CATALOG` (обложка `patterns` уже
  есть), имя в `studio_module_update_ui.py`, Core-хост, ветка упаковки, при
  необходимости `CapabilityProvider`. Заведение модуля и прав на сервере лицензий
  — отдельный административный шаг, не выводится из бандла.

### 4.3 UI (экраны, макеты — отдельный этап UI-approval)

1. Источник: свои PNG / загрузка плитки / (B+) промпт.
2. Настройки: раскладка, плотность, масштаб, поворот, зазор, частоты, фон
   (цвет/прозрачный), seed, закрепление. Для режима B не показывать
   неработающие «закрепить/переставить объект».
3. Предпросмотр: 3×3/5×5, линии границ вкл/выкл, стык в центре, увеличение шва.
4. Набор: N листов (разные seed/раскладки), QC-статус каждого листа.
5. Экспорт: размер/DPI/формат, оценка размера файла, папка, bundle map.

## 5. Нефункциональные требования

- Генерация листа 3600×3600 — не блокирует UI (Core-owned задача с lease);
  целевое время A < 10 с на типичной машине (замерить в задаче T-PERF).
- Память: композитинг в uint8 RGBA (3600² ≈ 52 МБ на буфер); float32 (≈ 207 МБ на
  RGBA-буфер) — только для полос шва и метрик; supertile half-drop/brick при
  ячейке 3600 = 3600×7200; лимиты из `studio_patterns` (сторона ≤ 8192,
  ≤ 64 MP рендер, ≤ 16 MP превью) с понятной ошибкой; оценка памяти до экспорта.
- Детерминизм: одинаковые входы + seed + версия алгоритма → попиксельно одинаковый
  результат в одной сборке (тесты сравнивают пиксели, не байты PNG: сжатие зависит
  от версии zlib/Pillow). Генератор случайных чисел — один явный (`random.Random`
  или `numpy.random.Generator(PCG64)`), без глобального состояния; между версиями
  алгоритма воспроизводимость обеспечивается сохранённой версией в проекте.
- Входные файлы не изменяются; результат пишется атомарно (temp + `os.replace`);
  отмена не оставляет частичный файл с «готовым» именем.

## 6. Вне объёма v1

Векторный экспорт SVG, ткань/текстильные профили, локальная диффузия с
circular padding, 3D-карты материалов (normal/roughness), мокапы товара
(остаются в отдельных workflow), Junk Journal (отдельный будущий модуль),
lattice-aware `make_seamless` для half-drop/brick (если не войдёт в v1).

## 7. Критерии приёмки

- Режим A: автотест против независимого lattice-oracle (как в
  `tests/test_studio_patterns.py`) — плитка, повторённая 3×3, попиксельно совпадает
  с бесконечной решёткой во всех раскладках, включая повёрнутые мотивы через
  углы и экспорт с масштабированием; `seam_score` = Ready для этих плиток (это
  проверка метрики, а не доказательство качества). Ручная проверка 20 наборов —
  на плотность, пустоты и заметность повтора.
- Режим B: на размеченном наборе плиток метрика шва после обработки лучше, чем до;
  плохие кейсы получают Review/Fail, а не молчаливый «успех»; пороги заданы до
  прогона приёмки.
- Экспорт 3600×3600 @300 DPI: размеры, DPI-метаданные (с допуском округления pHYs),
  sRGB, отсутствие альфы в JPG проверены автотестом.
- Подписанный пакет ставится и обновляется как остальные модули; Studio вне
  диапазона `studio_min`/`studio_max_exclusive` отклоняет; без права модуль не
  активируется и не загружается; отключение/удаление модуля не ломает проекты.
- Архитектурные тесты: нет импортов слоя Clipart/других модулей; Core не
  импортирует payload модуля.
- Ручная проверка владельцем в Qt-окружении (по правилам проекта) до релиза.

## 8. Риски

- Blend-метод в режиме B размывает/дублирует сложные рисунки → честные пороги QC,
  режим A и mirror как гарантированные пути.
- Шов от не-wrap-aware ресемплинга (экспорт 8×8/6×6, подгонка AI-плитки,
  суперсэмплинг) — самый вероятный тихий дефект; закрывается oracle-тестами.
- `module_id = patterns` фиксирован; после заведения права на сервере менять
  дорого.
- Новый Core-хост требует нового релиза оболочки и поднятия `studio_min`.

## 9. Решения владельца (2026-10-21)

1. `module_id = patterns`.
2. Перекраска по палитре — вне v1 (владелец: не нужна сейчас).
3. Передача из Clipart — вне v1; источник — свои PNG.
4. Режим B в v1: straight + mirror (решение за разработчика по поручению владельца:
   «делай как нужно»). Half-drop/brick доступны в режиме A (сцена). Lattice-aware
   вариант B — после v1.
