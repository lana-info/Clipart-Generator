# Windows 3.0.5 Provider-Aware Concurrency Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give KIE and PhotoRoom independent configurable limits of one to three tasks, enforce six total network tasks, preserve sequential local processing, then verify and build the final Windows 3.0.5 installer.

**Architecture:** Keep the existing per-image executor and indexed Results events. Add provider-specific semaphores around complete KIE and PhotoRoom calls, size network-capable runs for at most six image jobs, and retain the local-operation lock. KIE keeps its existing launch interval; PhotoRoom adds a bounded launch guard for its documented default of 60 images per minute.

**Tech Stack:** Python 3.11+, PyQt6, `concurrent.futures`, `threading`, Pillow, pytest/unittest, Azure Pipelines, Inno Setup 6.7.1.

**Spec:** `docs/superpowers/specs/2026-08-26-windows-3.0.5-stabilization-and-parallel-generation-design.md`

## Global Constraints

- Release version remains exactly `3.0.5`.
- KIE choices are exactly `(1, 2, 3)` with default `3`.
- PhotoRoom choices are exactly `(1, 2, 3)` with default `3`.
- No more than six remote image jobs may be active; local image operations remain sequential.
- Recraft request contracts and failure behavior remain unchanged; fal.ai is excluded.
- Topaz remains limited to 2x and 4x.
- No paid API request is used for source verification.
- The approved application illustrations and branded Inno Setup artwork must remain in the installed artifact.
- Server/update-service publication is excluded until target-Windows acceptance.

### Task 2: Parallelize PhotoRoom behind provider-aware limits

**Files:**

- Produce: `WorkerThread._wait_for_photoroom_launch_slot() -> None`

- [x] **Step 1: Replace the old PhotoRoom-serial test with failing provider tests**

  Using real worker scheduling, fake `_kie_create_task`/`_kie_wait_result`, and
  a fake PhotoRoom `_request_with_retries`, assert:

  ```python

  self.assertLessEqual(max_kie_active, 3)
  self.assertLessEqual(max_photoroom_active, 3)
  self.assertLessEqual(max_remote_active, 6)
  ```

  Add a separate PhotoRoom limit-1 case asserting `max_photoroom_active == 1`
  and retain the local-upscale case asserting `max_local_active == 1`.

- [x] **Step 2: Add a failing mixed-provider overlap test**

  Arrange six image pipelines so KIE work for later items can overlap with
  PhotoRoom work for earlier items. Assert both providers become active at the
  same time, each stays at or below 3, the total stays at or below 6, and every
  item records KIE before PhotoRoom.

- [x] **Step 3: Add failing cancellation and PhotoRoom 429 tests**

  Assert a stop request prevents pending entries from starting, active entries
  settle, a PhotoRoom failure affects only its item, and HTTP 429 retry remains
  bounded without duplicating successful outputs.

- [x] **Step 4: Verify RED**

  Run:
  `QT_QPA_PLATFORM=offscreen python -m pytest tests/test_generation_parallel.py tests/test_photoroom_provider.py -q`

  Expected: PhotoRoom reaches only one active task and the new setting/launch
  guard is missing.

- [x] **Step 5: Implement provider-aware scheduling**

  Create bounded KIE and PhotoRoom semaphores in `WorkerThread`. Hold a KIE slot
  for each complete KIE generation/model task and a PhotoRoom slot for the
  complete `_run_photoroom_remove_bg` request/response lifecycle. Remove only
  PhotoRoom from `_local_operation_lock`. Use up to six image workers when a
  run contains remote KIE or PhotoRoom work; keep local-only runs at one.

- [x] **Step 6: Implement the PhotoRoom launch guard**

  Under one lock, allow an initial burst no larger than the selected PhotoRoom
  concurrency and then pace sustained starts to one per second. Waiting must
  check cancellation and must never hold a provider semaphore while sleeping
  for another provider.

- [x] **Step 7: Verify GREEN and unchanged Recraft behavior**

  Re-run the focused tests plus:
  `QT_QPA_PLATFORM=offscreen python -m pytest tests/test_kie_model_contracts.py tests/test_processing_flow.py -q`

- [x] **Step 8: Commit the scheduler checkpoint**

  ```bash

  git commit -m "feat(worker): parallelize PhotoRoom safely"
  ```
