# Windows 3.0.5 Parallel KIE Stabilization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Every behavior change starts with a failing regression test.

**Goal:** Finish the accepted Windows 3.0.5 stabilization work, run all existing KIE image operations through one configurable parallel queue, and keep Results, completion, restart, and navigation accurate when tasks finish out of order.

**Architecture:** Add an indexed worker progress signal that is authoritative for Results rows, retain text progress only for logs and legacy workers, and schedule per-image pipelines through a bounded executor. KIE stages may overlap up to one global user setting; PhotoRoom and local stages use a single-operation lock. Each image keeps its own context and stage order.

**Tech Stack:** Python 3.11+, PyQt6, `concurrent.futures`, Pillow, unittest/pytest.

**Spec:** `docs/superpowers/specs/2026-08-26-windows-3.0.5-stabilization-and-parallel-generation-design.md`

## Global Constraints

- Do not start a Windows or macOS build in this implementation pass.
- Do not add fal.ai, change Recraft request payloads, or add silent provider fallbacks.
- Do not expose prompts, keys, provider URLs, raw responses, or full personal paths in user-facing progress.
- Preserve the selected stage order for each image and the existing bounded KIE launch/rate-limit behavior.
- Keep the sequential fallback when the KIE limit is 1.
- Keep Topaz choices limited to 2x and 4x.
- Preserve unrelated worktree changes and commit only verified files to the current feature branch.
