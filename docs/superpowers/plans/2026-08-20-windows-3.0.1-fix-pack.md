# Windows 3.0.1 Acceptance Fix Pack Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce a locally verified desktop fix pack for the confirmed Windows 3.0.1 acceptance findings without publishing a release or making paid/external actions.

**Architecture:** Keep strict online licensing, but distinguish a saved activation whose server is unavailable from a missing activation. Make the wizard shell responsive and lazy: only the selected mode controller and requested pages are constructed, completed pages are cached, and a determinate initialization overlay reports completed construction stages. Reuse one capability-aware processing editor contract in all modes.

**Tech Stack:** Python 3.12, PyQt6, unittest/pytest, existing V3 project-state and flow-controller modules.

**Spec:** `TASKS.md`, Task 65; `docs/testing/windows-3.0.1-acceptance-checklist.ru.md`, “Подтверждённый список исправлений для следующей Windows-сборки”.

## Global Constraints

- Do not allow offline authorization: every startup and protected action still requires a successful fresh server response.
- Do not expose full license keys, secrets, raw API responses, prompts, or personal paths in UI, logs, fixtures, or tests.
- Do not run paid providers, workers, deployment, artifact publication, or account actions.
- SynthID removal remains unavailable and must not be claimed.
- Keep the mode-selection license controls; remove license controls only from work pages.
- Preserve existing user data, mode state, selected folders, and completed outputs.
- Use test-first changes and checkpoint commits; do not touch unrelated dirty files.
