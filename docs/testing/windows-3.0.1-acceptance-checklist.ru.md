## Как отмечать результат

- `PASS` — ожидаемое поведение подтверждено.
- `FAIL` — обнаружена ошибка; записать шаги, сообщение и приложить скриншот.
- `BLOCKED` — проверка невозможна без тестовой лицензии, сервера или специальных
  условий.
- `SKIP` — проверка сознательно пропущена с указанной причиной.

Текущий ручной прогон остановлен владельцем после базовой установки,
лицензирования и локальной обработки. Все оставшиеся незаполненные пункты этого
документа считаются `SKIP / NOT TESTED`, а не подтверждённым `PASS`.

## Исправления, реализованные локально для 3.0.2

Все шесть пунктов ниже реализованы и покрыты локальными регрессионными тестами.
Их видимое поведение необходимо повторно подтвердить в Azure-сборке на Windows:

1. При недоступном интернете и сохранённой действующей активации показывать
   состояние «сервер лицензий временно недоступен» с повторной попыткой, а не
   предлагать заново ввести ключ. Доступ по старому результату не разрешать.
2. Заблокировать оставшуюся галочку согласия SynthID и подписать её
   «(недоступно)»; production-функцию удаления SynthID не заявлять.
3. Исправить «Продолжить с другими файлами»: видимый список и внутреннее
   состояние не должны расходиться. Сохранять ранее выбранные файлы для
   повторной обработки, пока пользователь сам их не удалит или не очистит.
4. Упростить и сделать адаптивной верхнюю панель: слева только текущий режим,
   справа только «Сменить режим», «Настройки API» и «Диагностика». Убрать
   дублирующие бренд/подзаголовок, лицензию и неверный статус «Не сохранено».
   При реальном сбое автосохранения показывать отдельное предупреждение.
5. Ускорить первое открытие режима: лениво создавать только нужную страницу,
   следующие загружать при переходе и затем кэшировать. Проверки оборудования
   не должны блокировать UI; заметная загрузка показывает честный процент
   завершённых этапов.
6. Привести общий блок обработки во всех трёх режимах к единому виду. Различия
   оставлять только там, где они действительно обусловлены сценарием; заменить
   необязательный технический английский понятными русскими подписями.

7. Упростить перегруженный интерфейс генерации промптов, сохранив текущий

- [ ] Журнал диагностики только после проверки, что в нём нет секретов.
- [ ] Версия Windows, шаги воспроизведения и ожидаемое/фактическое поведение для
  каждого `FAIL`.

## Критерий допуска к публикации

Релиз 3.0.2 можно рекомендовать к публикации, когда:

- все обязательные пункты имеют результат `PASS`;
- нет ошибки, позволяющей открыть приложение без свежей действующей лицензии;
- установка и обновление не повреждают предыдущую рабочую версию;
- неподписанный установщик показывает только ожидаемое предупреждение
  SmartScreen, после подтверждения устанавливается и запускается;
- сервер и клиент согласны по продукту, версии, размеру и SHA-256;
- все `BLOCKED`, `SKIP` и найденные дефекты явно перечислены и приняты до
  публикации.
