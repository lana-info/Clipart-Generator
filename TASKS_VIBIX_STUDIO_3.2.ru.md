## История ревью документации

### Chroma Key quality: отдельный обязательный поток перед VS-17

Основа VS-15: `chroma_key_selection.py` выбирает между текущими blue/green/red
по явным словам промпта на RU/EN и возвращает evidence/confidence. Это только
эвристика текста, не анализ результата. Исправление статуса: выбор по prompt
уже подключён в существующем генераторе; новый source sidecar описан вверху.
Будущий Auto/manual UI всё равно требует утверждения макета.

Текущий increment: `opaque_clipart` больше не применяет коррекцию цветов
полупрозрачных материалов. Legacy и защита исходного RGB непрозрачного объекта
сохранены. Сведения обработки версионированы `opaque-clipart-v2`, v1 читается
без переименования. Частичная CK-04: opt-in trace завершённых стадий,
счётчики/hash и known-truth метрики; внутренние reference/confidence ещё не
раскрыты. Шесть эталонов и 39 selector-проб сохраняют alpha/геометрию;
ошибка цвета уменьшена на двух эталонах, основная ошибка AA-маски остаётся.
Независимое ревью Terra выполнено, полная проверка: 1191 тест, 57 пропусков,
без ошибок. Это не завершение CK-05/06 и не готовность к Windows-релизу.

Следующий increment: offline geometry/topology и явные normal-profile ширины
добавлены в `chroma_quality.py`, с ограничением числа областей/пикселей/сэмплов.
`chroma_provenance.py` подключён к финальному PNG: hash-bound receipt удаления
фона, requested/observed removal key, профиль и `quality_status=not_evaluated`.
Это частичная CK-02/10a; generation metadata, Ready/Review, retry lineage,
полный trace и UI-приёмка остаются открытыми. Новые composite p95/max выявили
ошибки обычного AA на существующих known-truth fixtures. Эксперимент с
локальными опорными цветами отклонён: он ухудшал тонкие детали; его изменения
убраны, предыдущее рабочее исправление сохранено. Следующий шаг: независимая
оценка цвета объекта и уверенности на границе, проверка всех шести эталонов.
Не считать профиль полностью готовым.

Реализация поручена пользователем. Первый increment: `opaque_clipart` recovery
для воспроизведённого near-key opaque subject, подключение Local Chroma Key
через Worker, регрессия экспортированного PNG и `chroma_quality.py` с локальными
RGB/alpha mean/p95/max и композициями на трёх подложках. Скрипт
`scripts/benchmark_chroma_selector.py` воспроизводит 39 вариантов ключа и
сохраняет hash engine/input/truth. CK-01/02/03 частичны; это не общий единый
профиль, не production QC, не завершение VS-17. CK-04…11 остаются открытыми.

2026-09-09: после визуального дефекта цветной кромки проведён независимый
аудит `clipbrook-core` и текущего `chroma_key.py`. См.
`docs/research/clipbrook-core-chroma-audit-2026-09-09.ru.md` и
`PRD_CHROMA_KEY_QUALITY_V1.ru.md`. Зафиксирован синтетический регрессионный
дефект в автоматическом выборе precise/staged около порога 36; текущий VS-17
не может считаться готовым по наличию existing tests. До реализации VS-17
выполнить CK-01…CK-05 из нового PRD. CK-06…CK-11 образуют измеряемую замену
cutout profile и его продуктовую приёмку. Не переносить upstream AGPL-код в
runtime без отдельного лицензионного решения.
