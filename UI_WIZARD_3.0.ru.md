# Пошаговый интерфейс Clipart Generator 3.0

Статус: Screen specification
Технология: PyQt6, визуальное направление shadcn

## Общая оболочка

Окно состоит из четырёх зон:

1. верхняя строка: название проекта, рабочая папка, индикатор сохранения,
   настройки;
2. левая панель: название режима и вертикальный список шагов;
3. основная область: одна карточка текущего шага;
4. нижняя панель: «Назад», краткая проверка шага, «Далее» или «Запустить».

Технически маршрут удобно реализовать через `QStackedWidget`, отдельную модель
состояния проекта и небольшие QWidget-компоненты. Старый `QTabWidget` остаётся
доступен только на переходный период и не является оболочкой 3.0.

## Визуальный язык

- Фон окна: тёплый светло-серый; карточки: белые.
- Основной акцент: текущий бирюзовый цвет приложения, приведённый к единому
  design token.
- Скругление карточек и контролов: 8 px.
- Шаг сетки: 4 px; основные интервалы: 8, 12, 16, 24, 32 px.
- Заголовок экрана, одно короткое пояснение, затем элементы управления.
- Primary-кнопка одна на экран; опасные или платные действия визуально отделены.
- «Дополнительно» — сворачиваемая секция, закрытая по умолчанию.
- Ошибки показываются рядом с полем; длинный журнал не занимает основной экран.
- Все цвета, размеры и стили задаются централизованными PyQt6-токенами.

## Экран 0. Выбор задачи

Три крупные карточки:

- «Создать клипарт» — набор согласованных PNG;
- «Создать Pinterest-пины» — вертикальные изображения по промптам;
- «Обработать изображения» — фон, качество, очистка и проверка.

Каждая карточка содержит одну строку результата и кнопку «Начать». Ниже —
«Продолжить последний проект».

## Маршрут A. Клипарт

### A1. Проект

- Название проекта.
- Рабочая папка.
- Новый проект или продолжение сохранённого.

Переход доступен после выбора доступной для записи папки.

### A2. Содержание

Три способа:

- «Сгенерировать серию промптов»;
- «Вставить готовые промпты»;
- «Импортировать CSV».

Для генератора показываются поля: тема, список объектов, стиль, палитра,
композиция, фон, запреты, количество. Справа — живой пример одного промпта.

### A3. Проверка промптов

- Таблица промптов с быстрым редактированием.
- Референсы для выбранной строки.
- Поиск дублей и пустых строк.
- Действия: добавить, дублировать, удалить, изменить порядок.

### A4. Генерация

- Модель.
- Пропорция.
- Разрешение.
- Количество вариантов.
- Расчёт количества запросов и ориентировочной стоимости.
- «Дополнительно»: model-specific параметры.

### A5. Обработка

Верхняя часть — рекомендуемый рецепт «Готовый клипарт». Ниже — последовательная
лента операций:

`видимая метка → апскейл → удаление фона → апскейл → резкость → край → trim → экспорт`

Каждый включённый этап открывает только собственные параметры. Центр проверки
и очистки доступен отдельной карточкой, а не смешан с удалением фона.

### A6. Проверка и запуск

- Папка результата.
- Количество изображений.
- Модель и стоимость.
- Последовательность обработки.
- Предупреждения и отсутствующие обязательные поля.

Primary: «Запустить». После старта открывается общий экран выполнения.

## Маршрут B. Pinterest-пины

### B1. Проект

Название и рабочая папка.

### B2. Промпты

Те же три источника, что у клипарта. Генератор предлагает тему, цель пина,
визуальный сюжет, стиль, палитру, вертикальную композицию, safe zones и
ограничения. Это промпт для цельного изображения, не локальный редактор слоёв.

### B3. Проверка промптов

Редактируемый список, референсы, дубли и порядок.

### B4. Формат и модель

- Рекомендуемая вертикальная пропорция выбрана по умолчанию.
- Модель, разрешение, количество вариантов.
- Предпросмотр рамки пропорций.
- Стоимость до запуска.

### B5. Проверка и запуск

Резюме и пакетная генерация. Нет шагов текстового редактора, шаблонов бренда
или публикации в Pinterest.

## Маршрут C. Обработка изображений

### C1. Файлы

- Drag-and-drop и кнопка выбора.
- Список с миниатюрами, размерами, цветовым режимом и размером файла.
- Подтверждение: пользователь имеет право обрабатывать выбранные файлы.

### C2. Цель

Карточки рецептов:

- «Базовое улучшение»;
- «Подготовить клипарт»;
- «Проверить и очистить»;
- «Свой рецепт».

Рецепт только заполняет настройки; пользователь может их изменить.

### C3. Pipeline

Вертикальный упорядоченный список этапов. У каждого этапа есть toggle, краткий
результат и настройки. Недопустимые сочетания блокируются с объяснением.

Экспериментальная полная перегенерация, если будет одобрена benchmark-решением,
находится в отдельном предупреждающем блоке и не включается рецептом
автоматически.

### C4. Проверка и очистка

Три независимые карточки:

- «Данные файла»: EXIF/XMP/IPTC/generator fields;
- «Content Credentials»: наличие и состояние C2PA;
- «Пиксельные маркеры»: официальный handoff и статус доказательства.

Кнопки внешней проверки открывают соответствующий официальный сервис и не
загружают файл автоматически. Пользователь вручную фиксирует результат и
источник проверки.

### C5. Сравнение и запуск

- Ожидаемый порядок операций.
- Что будет сохранено и что очищено.
- Папка результата.
- Предупреждения о прозрачности, полном изменении пикселей и сетевой передаче.

### C6. Результаты

- Галерея «до/после».
- Статус каждого файла и этапа.
- Отдельные поля `processing`, `file_hints`, `pixel_evidence`,
  `verification_handoff`.
- Действия: открыть папку, повторить только ошибки, экспортировать отчёт.

## Общий экран выполнения

- Общий прогресс и текущий файл.
- Очередь с состояниями `ожидает / выполняется / готово / ошибка / отменено`.
- «Остановить после текущего файла» и безопасная отмена.
- Короткие пользовательские сообщения; технический лог открывается отдельно.
- Завершённые файлы остаются доступны даже при ошибке следующего файла.

## Состояния и навигация

- Каждый шаг имеет `incomplete`, `valid`, `warning`, `running`, `complete`.
- «Далее» недоступна только при блокирующей ошибке; предупреждение можно принять.
- Смена режима требует подтверждения только при несохранённых данных.
- Настройки режима сохраняются отдельно, чтобы пропорции Pinterest не меняли
  клипарт по умолчанию.
- При восстановлении 2.0-конфига параметры раскладываются по соответствующим
  шагам без изменения исходного файла конфигурации до первого сохранения.

## Accessibility и адаптация

- Минимальный размер окна: 980×700; при меньшей высоте прокручивается только
  содержимое карточки, а навигация остаётся видимой.
- Полная клавиатурная навигация и заметный focus state.
- Не полагаться только на цвет для ошибок и статусов.
- Контраст текста и контролов не ниже WCAG AA.
- Длинные русские и английские подписи не обрезаются без tooltip.

## Компоненты PyQt6

- `AppShell`: top bar, stepper, content, footer.
- `ModeCard`: карточка выбора режима.
- `StepList`: шаги и статусы.
- `FormCard`: заголовок, описание, content, validation.
- `AdvancedSection`: сворачиваемые параметры.
- `PipelineList`: порядок операций.
- `CostSummary`: запросы и ориентировочная стоимость.
- `EvidenceCard`: file hints, C2PA или pixel evidence.
- `BeforeAfterViewer`: синхронное сравнение.
- `RunQueue`: очередь и прогресс.

Компоненты повторяют принципы shadcn — простые карточки, единая типографика,
понятные состояния — но являются нативными классами PyQt6.
