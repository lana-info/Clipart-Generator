# PRD Clipart Generator 3.0

PRD Key: `CG3-PRD-001`

## Release scope clarification (manual smoke verified)

The mandatory 3.0 scope is the three user modes, wizard navigation, prompt and
reference editing, CSV mapping, model selection, processing, persistence,
credential settings, error handling and safe export. Manual smoke confirmed
these user-facing scenarios. Installer packaging, legacy WorkerThread
extraction, RunPod UX and production SynthID removal remain explicitly deferred
or blocked research work and are not release promises for the source-only 3.0
quality gate.

Статус: Revised after user testing
Целевая ветка: `develop/3.0`
Источник требований: комментарии ручного тестирования интерфейса 3.0
Файл задач: `TASKS_3.0.ru.md`

## Goal

Clipart Generator 3.0 должен быть понятным desktop-приложением для трёх
сценариев:

1. генерация клипарта по списку промптов и локальных референсов;
2. генерация изображений Pinterest-пинов по списку промптов и локальных
   референсов;
3. пакетная обработка существующих изображений.

Пользователь выбирает режим, рабочую папку и нужные файлы, после чего проходит
короткий одинаково устроенный маршрут. Приложение не требует создавать или
называть «проект», не показывает обязательных юридических подтверждений и не
заставляет проходить проверку файла или экспериментальные функции ради обычной
обработки.

## Users

- Автор цифровых товаров, пакетно создающий клипарт.
- Автор Pinterest-контента, генерирующий только изображения пинов по промптам.
- Пользователь, пакетно обрабатывающий локальные изображения.

## Product Principles

- `CG3-PR-001` — сначала задача пользователя, затем только относящиеся к ней
  настройки.
- `CG3-PR-002` — одинаковая сущность выглядит и работает одинаково во всех
  режимах.
- `CG3-PR-003` — папка и содержимое важнее искусственной сущности «проект».
- `CG3-PR-004` — основное действие доступно без обязательных экспериментальных,
  юридических или диагностических шагов.
- `CG3-PR-005` — исходные файлы никогда не перезаписываются.
- `CG3-PR-006` — интерфейс по умолчанию тёмный и сохраняет гарантированный
  контраст независимо от темы Windows.
- `CG3-PR-007` — сложные настройки показываются по требованию и только для
  выбранного провайдера.
- `CG3-PR-008` — прогресс объясняет, что выполняется сейчас, сколько уже сделано
  и что будет дальше.

## Revised Information Architecture

### 1. Оболочка приложения

- Главный экран содержит три карточки: «Клипарт», «Pinterest-пины»,
  «Обработка изображений».
- Переключение режима выполняется сразу, без предупреждения о несохранённых
  изменениях.
- Введённые данные каждого режима временно сохраняются в своей сессии и
  восстанавливаются при возврате.
- Название проекта не запрашивается. Рабочая сессия автоматически определяется
  режимом, выбранной папкой и временем запуска.
- Общие настройки приложения открываются из постоянной кнопки «Настройки».

### 2. Общие продуктовые компоненты

Архитектура должна состоять из общих компонентов, а не из трёх копий экранов:

- `WorkspaceSelector` — выбор рабочей/выходной папки.
- `PromptWorkspace` — единый редактор промптов и референсов для клипарта и
  Pinterest.
- `GenerationSettings` — выбор текстовой модели или модели с референсами,
  формата, разрешения и количества результатов.
- `ProcessingPipelineEditor` — единый блок обработки для всех трёх режимов.
- `ProviderSettingsPanel` — настройки только выбранного провайдера.
- `CredentialSettings` — API-ключи, проверка подключения и доступного баланса.
- `RunPlan` — неизменяемый план запуска, стоимость и проверка обязательных
  технических данных.
- `RunProgress` — этап, файл, общий процент, журнал и остановка.

Состояние UI хранится отдельно от рабочих сервисов. Общие компоненты получают
данные через адаптер режима, а pipeline формируется единым builder. Старое поле
`project_name` читается для совместимости черновиков 2.0/ранней 3.0, но не
требуется и не показывается пользователю.

## Functional Requirements

### Рабочие папки и файлы

- `CG3-FR-001` — в каждом режиме пользователь выбирает папку результата; в
  режиме обработки она явно отделена от списка исходных файлов.
- `CG3-FR-002` — название проекта отсутствует во всех пользовательских
  маршрутах и не участвует в валидации.
- `CG3-FR-003` — выбранные для обработки файлы показываются отдельными строками
  или карточками; возле каждого файла есть иконка корзины.
- `CG3-FR-004` — можно удалить один файл, очистить весь список и добавить новые
  файлы без повторного создания сессии.
- `CG3-FR-005` — выходная папка не может приводить к перезаписи исходников;
  конфликт имён разрешается безопасным суффиксом.

### Единый редактор промптов и референсов

- `CG3-FR-010` — «Промпты» и «Проверка промптов» объединены в один экран
  `PromptWorkspace`.
- `CG3-FR-011` — каждая строка содержит краткий текст промпта, число/миниатюры
  референсов и компактные иконки: дублировать и удалить.
- `CG3-FR-012` — новый промпт добавляется кнопкой с плюсом; весь список
  очищается явной кнопкой «Удалить все промпты».
- `CG3-FR-013` — строки меняют порядок drag-and-drop; кнопок
  «выше/ниже» нет.
- `CG3-FR-014` — двойной клик открывает полный текст промпта и все прикреплённые
  референсы; там можно изменить текст и удалить отдельные референсы.
- `CG3-FR-015` — референсы добавляются выбором одного или нескольких локальных
  файлов, а не вставкой текстового пути или URL.
- `CG3-FR-016` — референсы можно добавить к одному промпту, к выделенным
  промптам или ко всем промптам.
- `CG3-FR-017` — для выбранных или всех промптов можно удалить прежние
  референсы и заменить их новым набором.
- `CG3-FR-018` — импорт CSV сначала показывает сопоставление столбцов:
  пользователь сам выбирает столбец промпта, столбец референсов и наличие
  заголовка.
- `CG3-FR-019` — импорт CSV предлагает понятные действия «Добавить к списку»
  и «Заменить все промпты»; неоднозначной кнопки «Заменить список» нет.
- `CG3-FR-020` — ошибки CSV показываются после выбранного сопоставления
  столбцов и указывают конкретные строки.
- `CG3-FR-021` — список промптов, их порядок и локальные референсы
  автосохраняются отдельно для Clipart и Pinterest после каждого подтверждённого
  изменения и восстанавливаются при следующем запуске приложения.
- `CG3-FR-022` — кнопка «Удалить все промпты» полностью очищает промпты и
  связанные с ними референсы текущего режима и сохраняет очищенное состояние,
  чтобы удалённые данные не вернулись после перезапуска.
- `CG3-FR-023` — отдельная кнопка «Удалить все референсы» удаляет референсы у
  всех промптов текущего режима, но сохраняет тексты и порядок промптов.
- `CG3-FR-024` — если сохранённый локальный reference-файл больше не существует,
  промпт остаётся в списке, а reference помечается как недоступный и может быть
  заменён или удалён.

### Опциональный генератор серии

- `CG3-FR-025` — функция остаётся как необязательный раскрываемый блок
  «Создать варианты промптов по шаблону».
- `CG3-FR-026` — рядом показано короткое объяснение: функция создаёт несколько
  похожих промптов из темы, стиля и количества, но не запускает генерацию
  изображений.
- `CG3-FR-027` — перед добавлением показывается предпросмотр; пользователь
  выбирает «Добавить варианты» или «Заменить все промпты».
- `CG3-FR-028` — можно полностью игнорировать генератор серии и вставить готовые
  промпты построчно.

### Настройки генерации

- `CG3-FR-030` — выбор модели всегда виден на шаге генерации.
- `CG3-FR-031` — блок моделей с поддержкой референсов раскрыт по умолчанию,
  когда хотя бы у одного промпта есть референс.
- `CG3-FR-032` — неподходящие модели скрываются или отключаются с понятным
  объяснением.
- `CG3-FR-033` — Pinterest-режим генерирует только изображения пинов по
  промптам; публикация, редактор макета и обязательный текст поверх изображения
  не входят в 3.0.

### Единый блок обработки

- `CG3-FR-040` — клипарт, Pinterest и обработка изображений используют один
  `ProcessingPipelineEditor` с одинаковыми названиями, порядком и поведением.
- `CG3-FR-041` — доступны этапы: апскейл до удаления фона, удаление фона,
  апскейл после удаления фона, trim, очистка файла и экспорт 300 DPI.
- `CG3-FR-042` — порядок этапов показывается до запуска и соответствует
  фактическому pipeline.
- `CG3-FR-043` — для клипарта по умолчанию включены: апскейл до удаления фона,
  удаление фона, trim и экспорт 300 DPI.
- `CG3-FR-044` — апскейл после удаления фона доступен только через
  подтверждённый alpha-safe provider/profile. Несовместимый вариант скрывается
  или блокируется с объяснением; прозрачный результат нельзя молча превратить в
  непрозрачный.
- `CG3-FR-045` — для каждой операции настройки выбранного провайдера видны
  сразу под ней; настройки других провайдеров скрыты.
- `CG3-FR-046` — KIE, PhotoRoom, Local rembg, BEN2 и Local Real-ESRGAN
  показывают только реально поддерживаемые ими параметры.

### Очистка файла

- `CG3-FR-066` — все действия по очистке следов ИИ представлены единым первым
  блоком: метаданные, видимая метка и необязательная регенерация через KIE.

- `CG3-FR-050` — очистка включается одной галочкой «Очистить служебные данные
  файла».
- `CG3-FR-051` — очистка удаляет поддерживаемые EXIF, XMP, IPTC, комментарии,
  embedded thumbnails, generator fields и поддерживаемые embedded C2PA-блоки.
- `CG3-FR-052` — ICC-профиль и DPI всегда сохраняются; пользователь не видит
  переключателей их удаления.
- `CG3-FR-053` — внутренний preflight может проверять структуру файла для
  безопасной очистки, но отдельный обязательный шаг «Проверка файла» отсутствует.
- `CG3-FR-054` — режим «только очистка» обязан сохранять декодированные пиксели
  без изменений. Metadata stripping для PNG/JPEG выполняется без изменения
  пиксельного содержимого; требующее перекодирования преобразование считается
  отдельным этапом экспорта, заранее показывается в плане и не называется
  очисткой metadata.

### Экспериментальные функции и provenance

- `CG3-FR-060` — подтверждение «я имею право обрабатывать эти файлы» удалено.
- `CG3-FR-061` — «Разрешаю экспериментальную функцию» не является условием
  обычной обработки и не показывается, если экспериментальная функция не
  выбрана.
- `CG3-FR-062` — проверка AI-происхождения и SynthID находится в отдельном
  необязательном инструменте и не блокирует генерацию, обработку или экспорт.
  В 3.0 автоматическая онлайн-проверка не обещается: допускается локальный
  отчёт и ручной переход в официальный сервис. Любая будущая загрузка файла
  потребует отдельного явного действия, указания провайдера и privacy review.
- `CG3-FR-063` — экспериментальная перегенерация не входит в production
  pipeline до отдельного документированного решения по benchmark.
- `CG3-FR-064` — приложение не обещает «100% удаление SynthID» и отличает
  успешную обработку от результата независимой проверки.

### Research deliverable: benchmark SynthID

- `CG3-RS-001` — отдельно от production UI воспроизводимо сравниваются три
  метода из `SYNTHID_3_METHOD_BENCHMARK.ru.md`: M1 reverse-SynthID, M2
  diffusion/CtrlRegen и M3 structure-guided Qwen/Canny.
- `CG3-RS-002` — все методы проверяются на одном согласованном наборе наших
  файлов с зафиксированными входами, версиями моделей, параметрами и hardware.
- `CG3-RS-003` — для каждого метода измеряются официальные before/after
  evidence, визуальная близость, текст/лицо/композиция, alpha, время, стоимость,
  ошибки и operational feasibility.
- `CG3-RS-004` — отсутствие CUDA, бюджета, официальной проверки или допустимого
  провайдера оформляется как документированный `no-go`/`not-run`, а не как
  положительный или отрицательный результат метода.
- `CG3-RS-005` — итоговый ADR выбирает `adopt_local_experimental`,
  `adopt_worker_experimental`, `research_only` или `reject`; до ADR функция не
  включается в production UI.

### Настройки API

- `CG3-FR-070` — общие настройки содержат отдельные маскированные поля API-ключей
  KIE и PhotoRoom и могут расширяться через реестр провайдеров.
- `CG3-FR-071` — API-ключи хранятся в локальном пользовательском `.env` вне
  репозитория: `%LOCALAPPDATA%\Clipart Generator\.env` на Windows и
  `~/Library/Application Support/Clipart Generator/.env` на macOS. Приложение
  создаёт файл с максимально ограниченными доступными правами, не показывает
  его содержимое и никогда не выводит ключ в лог или текст ошибки. При первом
  запуске 3.0 legacy plaintext key атомарно переносится из `config.json` в
  `.env` и удаляется из config только после успешной записи и проверки.
- `CG3-FR-072` — возле провайдера есть действие «Проверить подключение».
- `CG3-FR-073` — «Проверить баланс» активно только если провайдер имеет
  подтверждённый balance endpoint; иначе действие disabled с подсказкой
  «Провайдер не предоставляет проверку баланса», а проверка подключения
  остаётся доступна.

### Выполнение и прогресс

- `CG3-FR-080` — после запуска сразу показываются текущий файл, номер файла из
  общего количества и текущий этап.
- `CG3-FR-081` — общий progress bar монотонно изменяется от 0 до 100 по мере
  завершения известных этапов; длительная операция показывает indeterminate
  activity, если провайдер не отдаёт точный процент.
- `CG3-FR-082` — текст статуса различает загрузку, ожидание провайдера,
  скачивание, апскейл, удаление фона, trim, очистку и сохранение.
- `CG3-FR-083` — пользователь может остановить очередь; уже сохранённые
  результаты остаются, исходники не меняются.
- `CG3-FR-084` — по завершении показаны папка результатов, успешные файлы,
  ошибки по отдельным файлам и действие «Открыть папку».

### Визуальная система и доступность

- `CG3-FR-090` — приложение использует собственную тёмную тему независимо от
  светлой/тёмной темы Windows.
- `CG3-FR-091` — основной текст светлый, фон тёмный, основные действия
  изумрудные/бирюзовые; цвет задаётся общими design tokens.
- `CG3-FR-092` — контраст обычного текста не ниже 4.5:1, крупного текста и
  значимых границ компонентов — не ниже 3:1.
- `CG3-FR-093` — disabled, focus, selected, error и success различимы не только
  цветом.
- `CG3-FR-094` — таблицы, выпадающие списки, подсказки, модальные окна и
  системные диалоги не наследуют неконтрастные системные цвета.

## Core Workflows

1. Клипарт: выбрать папку → заполнить единый список промптов и референсов →
   выбрать модель → проверить общий pipeline с рекомендуемыми значениями →
   запустить → открыть папку результата.
2. Pinterest: выбрать папку → заполнить тот же редактор промптов и референсов →
   выбрать вертикальный формат и модель → при необходимости включить общий
   pipeline → запустить → открыть папку результата.
3. Обработка: добавить файлы → удалить лишние строки при необходимости →
   выбрать выходную папку → настроить общий pipeline → запустить → увидеть
   прогресс и результаты.
4. Настройки: открыть постоянную кнопку → ввести ключ нужного провайдера →
   проверить подключение и, при поддержке API, баланс → сохранить.

## Technical Architecture

- `CG3-AR-001` — PyQt6 остаётся UI runtime; визуальный язык shadcn
  воспроизводится через нативные компоненты и токены.
- `CG3-AR-002` — `SessionState`/совместимый `ProjectState` хранит данные режимов
  без обязательного имени проекта; миграция старых черновиков сохраняется.
- `CG3-AR-003` — `PromptWorkspaceModel` и `PromptWorkspaceWidget` общие для
  клипарта и Pinterest; режим передаёт только defaults и ограничения.
- `CG3-AR-004` — `ProcessingRecipe` и `ProcessingPipelineEditor` общие для всех
  режимов; контроллеры режимов не копируют provider controls.
- `CG3-AR-005` — `ProviderRegistry` описывает capabilities, поля настроек,
  поддержку alpha, сетевую стоимость, проверку подключения и balance endpoint.
- `CG3-AR-006` — `RunPlanBuilder` создаёт одинаковый проверяемый план этапов для
  UI и worker, исключая расхождение отображаемого и реального порядка.
- `CG3-AR-007` — worker публикует структурированные progress events:
  `queued`, `file_started`, `stage_started`, `stage_progress`,
  `stage_finished`, `file_finished`, `failed`, `cancelled`.
- `CG3-AR-008` — credentials, пути, промпты и содержимое изображений не попадают
  в безопасный лог.
- `CG3-AR-011` — единый `EnvCredentialStore` читает и атомарно обновляет только
  пользовательский `.env`, ограничивает права файла на поддерживаемой ОС,
  работает fail-closed и мигрирует legacy plaintext credentials. Проектный
  `.env`, process environment и содержимое файла не сканируются и не логируются.
- `CG3-AR-009` — новые общие компоненты размещаются вне `main.py`; legacy
  pipeline подключается через адаптер до безопасного последующего извлечения.
- `CG3-AR-010` — черновик сессии автосохраняется по режиму; переход между
  режимами и перезапуск приложения не требуют подтверждения и не уничтожают
  введённые промпты или референсы.

## Constraints

- Desktop-приложение остаётся на Python/PyQt6.
- Рабочий pipeline 2.0 и старые настройки должны мигрировать без потери данных.
- Нельзя удалять или перезаписывать исходники пользователя.
- Новые зависимости не добавляются без отдельного решения.
- Пользовательский `.env` является выбранным локальным хранилищем секретов;
  файл не коммитится, не включается в сборку и не прикладывается к отчётам.
- Сетевые и платные операции показывают провайдера и оценку стоимости до
  запуска.
- API-возможности не выдумываются: баланс и параметры показываются только после
  подтверждения документацией/контрактом провайдера.
- 3.0 должна собираться для Windows и macOS существующим release-процессом.

## Out Of Scope

- Публикация или планирование публикаций в Pinterest.
- Редактор текста, брендовых слоёв и макетов Pinterest.
- Переписывание приложения на React/Electron.
- Обучение собственного AI-детектора.
- Обещание гарантированного удаления SynthID или доказательства человеческого
  происхождения.
- Обязательная проверка происхождения файла перед обычной обработкой.
- Автоматическая массовая отправка изображений во внешние детекторы.

## Acceptance Criteria

- [ ] `CG3-AC-001` — ни один основной маршрут не просит название проекта.
- [ ] `CG3-AC-002` — клипарт и Pinterest используют один экземпляр
  `PromptWorkspace`: локальные референсы, drag-and-drop, дублирование, удаление
  и полный редактор по двойному клику работают одинаково.
- [ ] `CG3-AC-003` — CSV с произвольными названиями столбцов импортируется после
  ручного сопоставления; ошибочные строки перечислены отдельно и не скрывают
  успешно распознанные.
- [ ] `CG3-AC-004` — все режимы используют один
  `ProcessingPipelineEditor`, одну модель рецепта и один builder фактического
  pipeline, а не визуально похожие копии.
- [ ] `CG3-AC-005` — очистка включается одной галочкой, удаляет заявленные
  служебные данные и сохраняет ICC/DPI.
- [ ] `CG3-AC-006` — клипарт впервые открывается с включёнными upscale-before,
  remove background, trim и 300 DPI.
- [ ] `CG3-AC-007` — настройки невыбранного провайдера скрыты; alpha-capability
  апскейла отображается до запуска.
- [ ] `CG3-AC-008` — у каждого выбранного файла есть отдельное удаление, а режим
  обработки имеет явную выходную папку.
- [ ] `CG3-AC-009` — обычная обработка не требует legal checkbox,
  experimental opt-in или отдельной проверки файла.
- [ ] `CG3-AC-010` — переключение режимов происходит без modal warning и
  сохраняет данные каждой сессии.
- [ ] `CG3-AC-011` — весь пользовательский текст читаем при тёмной теме Windows;
  тот же результат подтверждён при светлой теме Windows, потому что приложение
  использует собственную тёмную палитру.
- [ ] `CG3-AC-012` — во время обработки видны текущий файл, этап и изменяющийся
  общий прогресс либо честный indeterminate status.
- [ ] `CG3-AC-013` — API-ключи настраиваются в одном месте и не раскрываются в
  логах; баланс показывается только для подтверждённо поддерживаемых API.
- [ ] `CG3-AC-014` — исходники остаются неизменными, результаты сохраняются в
  выбранную папку без молчаливого перезаписывания.
- [ ] `CG3-AC-015` — offscreen smoke открывает каждый режим, возвращается без
  потери данных, строит run plan и отменяет тестовую очередь; ручной smoke
  подтверждает импорт CSV, работу референсов, выбор provider-specific настроек,
  удаление отдельного файла и видимый прогресс без сетевой оплаты.
- [ ] `CG3-AC-016` — bulk add/replace удаляет прежние референсы только в
  выбранной области, а удаление одного референса не затрагивает остальные.
- [ ] `CG3-AC-017` — reference-модели раскрыты при наличии референсов, а
  несовместимые модели недоступны с понятной причиной.
- [ ] `CG3-AC-018` — необязательный генератор серии показывает понятное
  объяснение и предпросмотр до добавления или замены промптов.
- [ ] `CG3-AC-019` — benchmark M1/M2/M3 создаёт сопоставимый evidence manifest и
  ADR либо документированно фиксирует невозможность каждого запуска.
- [ ] `CG3-AC-020` — после закрытия и повторного запуска Clipart и Pinterest
  восстанавливают собственные промпты, порядок и референсы; «Удалить все
  промпты» и «Удалить все референсы» независимо очищают и сохраняют ожидаемую
  область данных.
