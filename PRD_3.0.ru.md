# PRD Clipart Generator 3.0

Статус: Draft approved for task breakdown  
Целевая ветка: `develop/3.0`

## Goal

Версия 3.0 должна превратить перегруженный набор вкладок в понятный пошаговый
desktop-инструмент. Пользователь сначала выбирает задачу, после чего видит
только относящиеся к ней шаги и настройки.

Продукт поддерживает три сценария:

1. создание наборов клипарта;
2. создание изображений Pinterest-пинов по промптам;
3. обработка существующих изображений.

В 3.0 также входят управляемый генератор промптов и единый центр проверки и
очистки файла. Экспериментальная перегенерация для снижения обнаруживаемости
SynthID допускается только после отдельного benchmark и не должна заявляться как
гарантированное удаление происхождения изображения.

## Users

- Автор цифровых товаров, пакетно создающий клипарт для Etsy и других площадок.
- Автор Pinterest-контента, которому нужны готовые вертикальные изображения,
  сгенерированные по списку промптов.
- Пользователь, обрабатывающий собственные или лицензированные изображения:
  фон, апскейл, края, trim, видимые метки, metadata/C2PA и проверка происхождения.

## Product Principles

- Сначала задача пользователя, затем настройки.
- Безопасные рекомендуемые значения видны сразу; редкие параметры находятся в
  блоке «Дополнительно».
- Один экран — одно решение.
- Настройки, стоимость и ожидаемый результат показываются до запуска.
- Обработка файла и доказательство наличия/отсутствия маркера — разные факты.
- Файл не отправляется во внешний сервис без явного действия пользователя.
- Визуальный язык вдохновлён shadcn, но реализуется нативно на PyQt6.

## MVP

### 1. Оболочка пошагового интерфейса

- Стартовый экран с тремя карточками режимов: «Клипарт», «Pinterest-пины»,
  «Обработка изображений».
- Отдельный последовательный маршрут для каждого режима.
- Левая панель шагов, основная карточка текущего шага, нижняя панель
  «Назад / Далее / Запустить».
- Скрытие неприменимых настроек вместо одновременного показа всех параметров.
- Сохранение черновика текущего проекта и настроек каждого режима.
- Возможность вернуться на предыдущий шаг без потери введённых данных.

### 2. Режим «Клипарт»

- Выбор рабочей папки.
- Ввод, вставка или импорт списка промптов.
- Пошаговый генератор серии согласованных промптов.
- Поддержка референсов в рамках уже существующих ограничений приложения.
- Выбор модели, пропорций, разрешения и оценки стоимости.
- Настройка фонового удаления, апскейла, Unsharp Mask, очистки края, trim,
  экспорта PNG и 300 DPI.
- Итоговое резюме и пакетный запуск существующего pipeline.

### 3. Режим «Pinterest-пины»

- Создание только готовых изображений пинов по промптам.
- Ввод, импорт или генерация списка промптов.
- Вертикальные рекомендуемые пропорции; пользователь может выбрать другую
  поддерживаемую пропорцию.
- Выбор модели, разрешения, количества вариантов и рабочей папки.
- Итоговое резюме и пакетный экспорт изображений.
- В MVP нет редактора текста, макетов, брендовых шаблонов и публикации в
  Pinterest.

### 4. Режим «Обработка изображений»

- Выбор собственных или лицензированных локальных файлов.
- Выбор рецепта: базовая обработка, подготовка клипарта, проверка и очистка.
- Включение существующих операций: видимая метка, апскейл, удаление фона,
  Unsharp Mask, край, trim, metadata/C2PA cleanup.
- Предварительное отображение порядка операций.
- Отдельный opt-in для операций, меняющих всё изображение.
- Сравнение исходного и итогового файла и отчёт по каждому этапу.

### 5. Генератор промптов

- Входит в 3.0 как встроенный шаг режимов «Клипарт» и «Pinterest-пины».
- Поля для темы, объектов/сюжетов, стиля, палитры, композиции, фона,
  ограничений и количества вариантов.
- Генерация согласованной серии из шаблона без обязательного внешнего LLM.
- Предпросмотр, ручное редактирование, удаление дублей, изменение порядка и
  сохранение в существующий формат списка промптов.
- Для клипарта генератор по умолчанию добавляет требования к изолированному
  объекту и чистому фону; для пинов — к вертикальной композиции и безопасным
  зонам, но не рисует текст отдельным локальным редактором.
- AI-переформулирование промптов можно добавить позднее как опциональный
  провайдер; оно не является условием MVP.

### 6. Центр проверки и очистки

- Локальная проверка EXIF/XMP/IPTC, generator hints и C2PA.
- Отдельные результаты для metadata/C2PA и скрытых пиксельных маркеров.
- Для SynthID — официальный ручной handoff в Gemini с записью результата
  пользователем: `detected`, `not_detected`, `not_verified`, `unsupported`.
- Для изображений OpenAI — отдельный официальный handoff в OpenAI Verify, если
  сервис доступен пользователю.
- Сторонний AI-классификатор может быть подключён позднее только как
  эвристический сигнал с названием провайдера и его уверенностью.
- Отсутствие сигнала не обозначается как доказательство человеческого
  происхождения.
- Никакой автоматической загрузки во внешнюю проверку без отдельного согласия.

### 7. Экспериментальная перегенерация SynthID

- В MVP интерфейс и производственный pipeline не включаются до прохождения
  `SYNTHID_3_METHOD_BENCHMARK.ru.md`.
- Рассматриваются три разных класса методов: локальное спектральное
  преобразование, малосильная diffusion-перегенерация и
  structure-guided-перегенерация.
- Функция доступна только для собственных или лицензированных изображений после
  подтверждения пользователем.
- Интерфейс прямо сообщает, что все пиксели могут измениться, прозрачность может
  быть утрачена, а исходник всегда сохраняется отдельно.
- Успешное выполнение метода имеет статус `succeeded`, но не `removed`.
- Заявление о результате SynthID возможно только на основании отдельной
  официальной проверки входа и выхода.

## Core Workflows

1. Пользователь выбирает «Клипарт», создаёт серию промптов, выбирает модель и
   обработку, проверяет резюме и получает пакет готовых PNG.
2. Пользователь выбирает «Pinterest-пины», создаёт или импортирует промпты,
   выбирает вертикальный формат и получает пакет готовых изображений.
3. Пользователь выбирает «Обработка изображений», добавляет файлы, выбирает
   рецепт и операции, видит их порядок, запускает обработку и сравнивает
   результаты.
4. Пользователь открывает «Проверку и очистку», получает локальный отчёт,
   удаляет выбранные file-level данные и при необходимости вручную проверяет
   SynthID/OpenAI provenance в официальном сервисе.
5. После успешного benchmark пользователь может отдельно включить
   экспериментальную перегенерацию, сохранить варианты и повторно вне
   приложения проверить их официальным детектором.

## Constraints

- Desktop-приложение остаётся на Python/PyQt6; React/Tailwind/shadcn в runtime не
  добавляются.
- Существующий рабочий pipeline 2.0 и пользовательские настройки должны
  мигрировать без потери данных.
- Монолитный `main.py` нельзя расширять ещё одним большим блоком интерфейса:
  новые экраны, состояние маршрута и дизайн-токены выделяются в модули.
- Нельзя удалять или перезаписывать исходники пользователя.
- Сетевые и платные действия требуют явного согласия и предварительной оценки
  стоимости.
- API-ключи, локальные пути, промпты и содержимое изображений не попадают в
  безопасный лог.
- Внешние детекторы и генераторы считаются недоверенными до отдельного
  security/privacy review.
- Прозрачность не является обязательной для SynthID-эксперимента, но её потеря
  должна измеряться и показываться.
- Статусы скрытых маркеров должны соответствовать
  `PIXEL_WATERMARK_STATUS_CONTRACT.md`.
- 3.0 должна собираться для Windows и macOS тем же release-процессом, что и 2.0.

## Out Of Scope

- Публикация или планирование публикаций в Pinterest.
- Локальный редактор текста, брендовых слоёв и макетов Pinterest.
- Переписывание приложения на React/Electron.
- Обещание «100% удаления SynthID» или «изображение создано человеком».
- Автоматическое массовое отправление изображений в Gemini, OpenAI Verify или
  сторонние онлайн-детекторы.
- Обучение собственного AI-детектора в 3.0.
- Поставка многогигабайтных diffusion-моделей внутри desktop-дистрибутива без
  отдельного решения по инфраструктуре и лицензиям.

## Acceptance Criteria

- [ ] После запуска пользователь видит три режима и не видит весь набор
  технических настроек одновременно.
- [ ] Каждый режим можно пройти от выбора задачи до результата с возвратом назад
  без потери данных.
- [ ] Режим клипарта использует существующую генерацию и обработку без
  регрессии поддерживаемых провайдеров.
- [ ] Режим Pinterest создаёт пакет изображений по промптам и не содержит
  публикации, редактора макетов или обязательного текста поверх изображения.
- [ ] Генератор создаёт редактируемую согласованную серию промптов для обоих
  генеративных режимов.
- [ ] Режим обработки показывает точный порядок включённых операций до запуска.
- [ ] Центр проверки различает file-level hints, processing status и
  pixel-level evidence.
- [ ] Внешняя передача файла невозможна без явного действия пользователя.
- [ ] Исходные файлы остаются неизменными; результаты сохраняются в новую папку.
- [ ] SynthID-эксперимент не включён в продукт до документированного решения по
  benchmark.
- [ ] Ни один статус UI или отчёта не превращает `succeeded` или
  `not_detected` в недоказанное `removed`/«создано человеком».
- [ ] Старые конфиги и сохранённые промпты 2.0 загружаются в 3.0.
- [ ] Автоматические тесты и offscreen smoke проходят на поддерживаемых
  платформах.

## Open Questions

- Какой из трёх SynthID-методов пройдёт pilot и допустим ли для него отдельный
  GPU/cloud worker.
- Нужен ли после MVP опциональный AI-провайдер для переформулирования промптов,
  или шаблонного генератора достаточно.
- Какой официальный или партнёрский API проверки provenance станет доступен для
  автоматизации; до этого используется только ручной handoff.
