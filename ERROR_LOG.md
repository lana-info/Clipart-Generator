# Журнал ошибок

## 2026-08-31 — Fal-апскейл публиковал лишний rough и повторно скачивал результат

- Симптом: для 17 апскейлов в `rough/` появлялись 34 файла, финальные PNG
  скачивались с Fal повторно, а отсутствующий итог мог быть отмечен успешным.
- Корневая причина: подготовительный Recraft PNG совпадал с широким маркером
  `upscaled`; после первого скачивания worker продолжал считать URL главным
  результатом; проверка финала возвращала `unreadable`, но не останавливала
  успешное завершение.
- Исправление: rough-классификация принимает только точные имена результатов,
  локальный Fal PNG используется для финального экспорта, а опубликованный итог
  обязан быть непустым читаемым PNG до события успеха.
- Регрессия: `tests/test_v3_output_paths.py`, `tests/test_kie_routing.py` и
  `tests/test_final_save_cleanup.py`. Полный набор: 1091 passed, 57 skipped,
  2 deselected, 146 subtests.
- Остаточный риск: старая диагностика доказывает ложную отметку успеха, но не
  показывает внешнее событие, удалившее конкретный файл после публикации.

## 2026-08-31 — запуск только с экспортом 300 DPI отклонял все файлы

- Симптом: пакет из 81 файла завершался за секунду с 81 ошибкой и сообщением
  об отсутствии обязательной настройки запуска; в `rough/` ничего не создавалось.
- Корневая причина: `export_300_dpi` поддерживался финальным сохранением, но был
  пропущен в начальной проверке «включён хотя бы один этап».
- Исправление: экспорт 300 DPI признан самостоятельным локальным этапом и не
  требует API-ключа или другого преобразования.
- Регрессия: `tests/test_local_processing_acceptance.py` проверяет DPI-only
  обработку и фактическое значение 300 DPI в итоговом PNG.

## 2026-08-31 — добавление 81 больших изображений блокировало интерфейс

- Симптом: при перетаскивании 81 крупного апскейленного PNG программа надолго
  переставала отвечать до появления списка.
- Корневая причина: каждый файл полностью декодировался на UI-потоке при
  добавлении, повторно проверялся при немедленном refresh, затем все миниатюры
  синхронно декодировались подряд.
- Исправление: импорт и формирование запроса проверяют заголовки без пиксельного
  декодирования, метаданные кэшируются по пути/размеру/mtime, а миниатюры пакетов
  свыше 20 файлов загружаются по очереди через Qt. Полная декодируемость каждого
  исходника проверяется в worker до платного Fal-вызова.
- Регрессия: `tests/test_v3_processing_flow.py` моделирует пакеты из 81 и 40
  файлов; `tests/test_kie_routing.py` не допускает платный вызов для повреждённого
  файла.

## 2026-08-31 — итог запуска подменял реальную ошибку на missing_completion

- Симптом: отдельные файлы уже имели понятную причину ошибки, но технический
  итог всего запуска записывался как `missing_completion`.
- Корневая причина: `handle_finished()` выбирал этот код при наличии любого
  элемента со статусом `failed`, а не только незавершённых `pending/running`.
- Исправление: безопасный код сохраняется на элементе; итог наследует единую
  причину, использует `multiple_item_failures` для смешанного набора и оставляет
  `missing_completion` только реальному нарушению протокола завершения.
- Регрессия: `tests/test_v3_run_queue.py` покрывает единую, смешанную и истинно
  отсутствующую причину завершения.

## 2026-08-26 — Topaz не создавал задачу KIE

- Симптом: апскейл завершался ошибкой, а в журнале задач KIE не появлялся
  запрос.
- Корневая причина: приложение использовало устаревший ID `topaz/upscale` и
  принудительно формировало неподдерживаемые 8× вместо выбранных 4×.
- Исправление: интеграция переведена на `topaz/image-upscale`, масштаб ограничен
  документированными 1×/2×/4×, старые настройки мигрируют автоматически, а
  локальный файл проверяется до загрузки и создания платной задачи.
- Регрессия: `tests/test_kie_routing.py`, `tests/test_v3_project_state.py`,
  `tests/test_v3_provider_registry.py` и `tests/test_v3_processing_editor.py`.

## 2026-08-14 — installer собирал клиент со старым протоколом лицензий

- Симптом: release workflow мог собрать Clipart Generator 3.0, но desktop-клиент
  обращался к legacy-маршрутам `/activate`, `/validate` и `/status`, тогда как
  развёрнутый License Service принимает `/api/v1/licenses/activate` и
  `/api/v1/licenses/validate` с Ed25519-доказательством устройства.
- Корневая причина: сервер и desktop-разработка завершались раздельно, а в
  release gate не было межпроектного contract-теста. Наличие старых локальных
  тестов клиента ошибочно выглядело как готовая интеграция.
- Исправление: desktop переведён на фиксированный HTTPS endpoint, стабильный
  `product_id`, свежие nonce/proof и проверку подписанного ответа по закреплённому
  публичному ключу. Офлайн-разрешение удалено; все три V3 worker boundary
  требуют успешной онлайн-проверки.
- Регрессия: `tests/test_license_client_security.py`,
  `tests/test_v3_license_flow_gate.py` и
  `tests/test_license_service_contract.py` проверяют подпись, границы запуска и
  полный цикл «выпуск → активация → проверка → отзыв → отказ».

## 2026-08-14 — повтор неуспешной операции обходил онлайн-проверку

- Симптом: первый запуск требовал действующую лицензию, но кнопка повторного
  запуска после ошибки могла создать новый worker без повторной проверки.
- Корневая причина: retry-путь находился в общей очереди результатов и не
  проходил через обычный `start()` конкретного режима.
- Исправление: непосредственно перед созданием retry-worker вызывается тот же
  обязательный `authorization_provider`; любой отказ останавливает повтор.
- Регрессия: `tests/test_v3_run_queue.py` проверяет как повторную авторизацию,
  так и отсутствие нового worker при недоступной или отклонённой лицензии.

## 2026-08-14 — workflow мог завершиться без доступного инсталлятора

- Симптом: шаг загрузки Windows-артефакта имел `continue-on-error: true`, поэтому
  ошибка публикации файла не делала сборку неуспешной.
- Корневая причина: выгрузка результата считалась необязательным действием,
  хотя для этой задачи сам инсталлятор является обязательным результатом.
- Исправление: загрузка артефакта стала обязательной, а отсутствие `.exe`,
  `.sha256` или файла версии теперь завершает workflow с ошибкой.
- Регрессия: release workflow использует `if-no-files-found: error`; после
  сборки скачанный SHA-256 дополнительно сверяется локально.

## 2026-08-15 — приложение открывалось без startup-проверки лицензии

- Симптом: установленное приложение открывало выбор режима без запроса ключа;
  ввод лицензии был доступен только через малозаметную кнопку внутри режима.
- Корневая причина: онлайн-авторизация была установлена на границах worker и
  retry, но фактическая release-точка входа вызывала
  `create_v3_application_window()` без обязательного startup-барьера.
- Исправление: release-точка входа создаёт основное окно только после свежей
  онлайн-проверки сохранённой лицензии либо успешного ввода и повторной проверки
  нового ключа. Отмена, отсутствие gate, офлайн или отказ сервера закрывают
  запуск до показа основного интерфейса.
- Регрессия: `tests/test_release_entrypoint.py` проверяет отказ до открытия,
  онлайн-проверку сохранённой лицензии, повторную проверку после активации и
  fail-closed поведение при отсутствующем gate. Release workflow также запускает
  новый `--release-entrypoint-smoke` внутри собранного `.exe`; он проверяет
  наличие маскированного поля ключа и отказ startup при отклонённой лицензии.

## 2026-08-15 — установленное приложение предлагало Program Files для результатов

- Симптом: у нового проекта не было сохранённой рабочей папки, поэтому системный
  диалог мог открываться в каталоге установленного `.exe`, включая `Program Files`.
- Корневая причина: V3 сохраняла часть выходных путей по режимам, но не задавала
  общий пользовательский путь новому проекту; резервом был `os.getcwd()`.
- Исправление: первый путь берётся из системной папки изображений как
  `Pictures/Clipart Generator`; отдельно сохраняются последние рабочая папка и
  папка результата обработки. Недоступный старый путь возвращает безопасный
  пользовательский вариант.
- Регрессия: `tests/test_v3_mode_selection.py` проверяет новый путь независимо от
  каталога процесса и восстановление обоих выбранных путей после перезапуска.
