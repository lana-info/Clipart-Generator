# PRD: предсказуемое Chroma Key удаление фона

Дата: 2026-09-09. Версия: 1. Статус: пользователь поручил реализацию; выполняется поэтапно.
Основание: [аудит Clipbrook Core](docs/research/clipbrook-core-chroma-audit-2026-09-09.ru.md).

Первый ограниченный increment: явный профиль `opaque_clipart` для существующего
Local Chroma Key, исправление воспроизведённого near-key opaque случая и
измерение RGB/alpha выбросов. Это не завершение CK-01…11: единый общий pipeline,
внутренний mask/reference/confidence trace, Ready/Review и утверждение полного QC
остаются открытыми. Добавлены sidecar сведений обработки и opt-in trace
завершённых pixel-stages. Профиль v2 пропускает коррекцию полупрозрачного
материала для opaque clipart; основная ошибка AA-маски ещё не исправлена.

## Цель

Checkpoint 2026-09-10 после разбора вложений: действующий основной профиль
остаётся opaque subject → поддержанный chroma → local keyer → конечный QC.
Четыре live-пробы KIE стоили $0.12: два transparent-prompt результата имеют
RGBA, но это не доказывает чистоту края; native-prompt венок имеет дымку.
Текущий chroma визуально лучше в этих двух сюжетах, не принят как универсально
готовый алгоритм. ZIP-кандидат не заменяет движок из-за эталонных регрессий.
Сохранение уже имеющейся alpha подключено к Worker, но общий Ready/Review и
generation-side requested/observed контракт ещё не завершён. Добавлен узкий
source-sidecar: requested цвет до API, SHA256 после скачивания, чтение при
повторной обработке. Job/Attempt и общий QC это не закрывает. Полная бинаризация,
глобальная gamma и пары независимых white/black генераций не являются финишем.
Полупрозрачные материалы отложены, AA тонких непрозрачных деталей сохраняется.
Детальные результаты: [сравнение](docs/research/attached-pipeline-review-2026-09-10.ru.md).

Дать автоматическому Clipart-пайплайну качественное и предсказуемое удаление
однотонного chroma-key фона: без создания красных, жёлтых, зелёных и иных
ложных цветных обводок, с сохранением непрозрачных волос, веточек, листьев,
отверстий и мелких деталей. Конечный PNG имеет прозрачный фон; край остаётся
резким. Если сглаживание неизбежно, его ширина не превышает 1–2 px в финальном
разрешении, кроме истинной coverage субпиксельной тонкой детали.

## Пользователь и основной сценарий

Пользователь генерирует или открывает клипарт с сохранённым цветом фона.
Приложение само применяет этот цвет, проверяет пригодность изображения и
создаёт PNG. Пользователь не выбирает пороги и не пишет технические части
prompt. При сомнении приложение не портит изображение молча: предлагает
понятный fallback либо локальную правку контура/alpha.

Импортированная картинка без metadata сохраняет режимы Auto detect и ручной
выбор цвета. Этот PRD не меняет prompt builder, выбор chroma цвета, sidecar,
модель генерации или редактор контура, кроме их контракта с обработчиком.

## Подтверждённые основания

| Основание | Последствие для продукта |
| --- | --- |
| Синтетика доказала скачок `precise/staged` возле второго канала key = 36 и ложный красноватый край | Убрать незафиксированное переключение разных математических путей или сделать его безопасно диагностируемым и непрерывным. |
| Одно подавление цвета ключа способно создать его красно-жёлтое дополнение | Проверять полный RGB error и композиции на подложках, а не только остаток ключевого канала. |
| У тонких веток нет глубокого interior reference | Использовать multi-depth reference с измеримой уверенностью; не удалять маленькие компоненты глобально. |
| Поздние cleanup/upscale могут испортить уже хороший keying | Измерять и тестировать именно конечный PNG. |
| Объект может действительно содержать chroma-цвет | Не исправлять opaque RGB только по сходству с key; нужны локальность, reference и confidence. |

## Функциональные требования

### CK-01. Единый диагностируемый путь

- Автоматический режим использует единый versioned processing profile вместо
  скрытого скачка между `precise` и `staged` по значению 36.
- Для каждого результата сохраняются: requested/observed key, версия профиля,
  выбранный fallback, флаги уверенности и итоговое решение Ready/Review.
- Если border не подтверждает однородный насыщенный key, chroma removal не
  делает вид, что результат надёжен.

### CK-02. Маска из трёх зон

- До восстановления цвета строятся зоны: уверенный фон, уверенный объект,
  transition band.
- Уверенный объект, расположенный далеко от фона, не превращается в фон только
  по сходству с chroma-цветом.
- Подозрительная key-загрязнённая кромка может быть переведена из core в band
  только при подтверждённом локальном interior reference; тёмные тонкие детали
  имеют отдельную защиту.

### CK-03. Восстановление цвета края

- Цвет transition band рассчитывается как смесь foreground/key с контролем
  устойчивости уравнения и ограничением значений до последующих этапов.
- Reference foreground собирается маско-взвешенно, на нескольких глубинах;
  тонкие детали используют наиболее глубокую доступную надёжную опору.
- Слабый или почти чёрный reference не используется для уверенного hue repair.
- Цвет корректируется лишь в зоне с подтверждённой примесью фона. Внутренний
  непрозрачный RGB не изменяется глобально.

### CK-04. Топология и мелкие детали

- Внутренние области, соединённые с внешним фоном, можно рассматривать как
  кандидаты на background; изолированные области не удаляются только по цвету.
- Очистка маленьких islands отключена по умолчанию для clipart profile.
- Отверстия, концы, развилки и отдельные полезные мелкие компоненты проходят
  специальные регрессии.

### CK-05. Конечный PNG и разрешённые маршруты

- Для каждого допустимого resize/upscale/edge-cleanup маршрута задан контракт:
  alpha-preserving verified output либо локальный premultiplied-alpha resize.
  Внешний provider без такого контракта не применяется после появления alpha;
  маршрут переносится до удаления фона либо получает Review.
- Любой cleanup имеет profile setting, журнал и regression fixtures; MinFilter
  не применяется без доказательства, что не срезает целевые тонкие детали.
- Входная alpha провайдера сохраняется и не повышается обработчиком.

### CK-06. UX и fallback

- Для готовой генерации пользователь видит только исход изображения,
  результат и понятный статус, без технических порогов.
- При низкой уверенности доступны: повторить удаление с Auto detect/manual key,
  открыть редактор прозрачности/контура, либо оставить исходник. Повторная
  генерация — отдельное решение пользователя и не запускается автоматически.
- Техническая диагностика доступна по запросу/support bundle без API keys,
  оригинальных prompt или лишних пользовательских данных.

### Контракт состояния и повторной обработки

- Состояния `Ready`, `Review` и `Failed` различаются в данных и интерфейсе.
- Sidecar/project record атомарно хранит hash source/result, requested и
  observed key, processing profile/version, confidence/reason, retry lineage
  и выбранное пользователем действие. Неверный hash или отсутствующий sidecar
  не подставляет key молча.
- Auto detect возвращает конкретный observed RGB и confidence, а не только имя
  цвета. Manual key сохраняет requested RGB отдельно. Retry не перезаписывает
  предыдущий результат и имеет правила для noisy border, wrong/missing sidecar
  и key-colored foreground.
- Передача исходника, результата и состояния в editor является контрактом;
  сохранение/восстановление editor history остаётся задачей VS-19–21.

## Нефункциональные требования и качество

- Основной профиль: непрозрачный clipart. Сетка, дым, стекло и полупрозрачные
  материалы prompt не допускает; они не являются критерием этого профиля.
- Нет доказанных ложных chroma/complement выбросов на approved fixtures выше
  согласованного порога p95/max. Порог устанавливается до выпуска после
  baseline benchmark, не подбирается задним числом.
- Переход alpha шире 2 px запрещён в непрозрачной части контура. Исключение:
  known-truth subpixel coverage тонкой линии.
- Улучшение не принимается, если средняя метрика лучше ценой потери holes,
  развилок или кончиков веточек/волос.
- Производительность и память фиксируются на утверждённых размерах fixtures;
  нет неявного облачного API и дополнительных платных вызовов.

## Явно вне объёма

- Перенос upstream code или существенных code-derived fragments. Лицензионная
  совместимость и способ использования вне объёма этого PRD; до отдельной
  проверки их не включать в runtime.
- Облачная сегментация/маттинг как скрытая обязательная зависимость.
- Автоматическая повторная генерация с расходом кредитов.
- Универсальное обещание корректно отделить объект, если он того же цвета, что
  и фон, без пространственной или иной дополнительной информации.
- Массовое размытие, эрозия, downscale/upscale как маскировка дефекта.

## Открытые решения до CK-06

1. Точные numeric thresholds качества и набор реальных пользовательских
   fixtures утверждаются в CK-02b до изменения профиля.
2. Решение об optional segmentation/matting fallback принимается только после
   измеренного результата локального pipeline; этот PRD не утверждает API,
   цену или модель.
3. Политика обработки частично прозрачных импортированных изображений остаётся
   отдельным профилем. Основной clipart профиль непрозрачный.

## Acceptance criteria выпуска

- [ ] На known-truth наборе есть измеренные alpha/RGB/contour/topology результаты
      до и после, включая p95/max и три подложки.
- [ ] Нет порогового скачка, эквивалентного найденному 36→37, без явного
      Review/fallback.
- [ ] Непрозрачные волосы, веточки, отверстия и отдельные мелкие детали не
      регрессируют согласно утверждённым метрикам.
- [ ] На финальном PNG соблюдён предел края 1–2 px, кроме known-truth coverage.
- [ ] Истинные key-colored элементы не вырезаются только из-за цвета.
- [ ] Пользователь видит простой результат и безопасные действия при сомнении;
      Ready/Review/Failed и provenance корректно переживают restart/transfer.
- [ ] Нет нового платного API или лицензируемой runtime-зависимости без
      отдельного согласования.
